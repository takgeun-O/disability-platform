# P03 게시본 UX 검토 — 1단계 보완 후

확인일: 2026-09-26. 대상: [IYUM 게시 홈](https://ochre-bead-10600476.figma.site), [P03 게시 경로](https://ochre-bead-10600476.figma.site/validation/hearing-aid-health-insurance).

이전 [v47 미리보기 검토](./P03-Figma-Stage1-Review-2026-09-26.md)와 다른 시점의 **실제 공개 사이트**를 확인했다. 게시 소스의 Make 버전 번호는 확인하지 않았다. 비교 기준은 [원본 Handoff](./P03-Figma-Handoff.md)다. 아래 내용은 검토와 제안이며, 새 동작을 승인·구현한 기록이 아니다.

**후속 합의 기록(2026-09-26):** 이 검토 이후 사용자가 검토한 모든 내용에 동의했다. [보완 요청문](./P03-Figma-UX-Refinement-Prompt.md)과 Handoff §4.2에 실행 방향을 반영했다. 아래 관찰은 수정 전 게시본 기준이며, 합의된 보완의 구현·검증 완료를 뜻하지 않는다.

## 1. 실제 확인 범위

- 홈의 P03 항목, 복지 메뉴 → 안내 목록 → P03 진입, 시작 화면, 질문 Q1–Q4.
- 결과 7개: 검사·진단 중(R02), 심사 대기(R03), 등록 상태 모름(R04), 의료급여(R05), 첫 지원(R08), 지원 이력 모름(R10), 보험·처방 모두 모름(R12).
- 질문 ‘변경’, 보험 답변 변경 시 후속 답변·결과 초기화, 첫 지원의 후속 절차 상세 펼치기.
- R08 ‘지금 할 일 보기 ↓’ Enter 조작과 제목 초점 도달.
- 기본 브라우저 폭, 1280px, 390px, 320px에서 관련 표본 화면/DOM 관찰. 390/320px의 관찰 화면에서 문서 가로 넘침은 없었다. 임시 화면 크기는 원복했다.
- Make 소스, 전체 15개 결과 회귀, 복사 성공·실패, 화면낭독기, 실물 모바일, 서버 전송·저장 여부는 이번 검토에서 확인하지 않았다. 앱 수정·빌드·배포는 하지 않았다.

## 2. 개선된 부분

- 공개 URL에서 통합 P03을 실제로 열 수 있다. 홈의 탐색·커뮤니티 구조를 유지하면서 복지 영역과 메뉴에서 진입한다.
- 질문 상단 5단계가 추가되었고, 이번에 확인한 대표 결과 외 분기에도 본문 절차 표시가 있다.
- 상위 답변을 변경하면 뒤의 답변과 결과가 제거된다. R10은 이전 지원 기록의 존재부터 확인하도록 안내한다.
- 개인별 센터 질문이 비용 상세보다 앞에 배치되고, 빠른 이동은 제목으로 초점을 옮긴다.

## 3. 사용자가 제기한 다섯 항목

| 항목 | 확인한 사실 | 권장 방향 |
| --- | --- | --- |
| 기본 흐름 문구 위치 | ‘아래는 기본 흐름이에요…’가 본문 단계 표시 뒤에 있다. | 본문 제목 → 적용 범위 문구 → 단계 안내 순서로 옮긴다. 동일 문구를 상·하단에 반복하지 않는다. |
| 지금 할 일 강조 | 일반 카드와 같은 배경·테두리 계열이며, 문의 인용문도 회색 배경이다. | 이 영역에만 은은한 강조 배경·뚜렷한 제목·기관/핵심 행동의 굵기를 사용한다. 문단 전체나 여러 섹션을 강한 색으로 칠하지 않는다. |
| 선택 후 화면 전환감 | URL은 유지되지만 선택지를 제거하고 답변 요약/‘변경’으로 치환한다. 바로 다른 선택지를 고를 수 없다. | 결과를 만든 마지막 질문과 선택지는 남기고 바로 아래 결과를 펼친다. 부드러운 이동은 결과 시작까지만 한다. 답변 변경 시 같은 결과 영역을 갱신한다. |
| 검정/연노랑 혼용 | 검사 중·첫 상담은 검정, 등록/지원 이력/보험 등 확인 필요는 연노랑으로 보인다. | 강조 색상은 공통 계열로 통일할 수 있으나 ‘진행 중’과 ‘확인 필요’의 의미는 글자/아이콘/테두리로 보존한다. 미확인을 ‘현재 단계 확정’으로 바꾸지 않는다. |
| 단계 선택과 상세 | 단계는 클릭·키보드 조작을 제공하지 않는 일반 요소다. 후속 절차는 R08 하단의 다른 펼침 안에 있다. | 본문 단계 안내에 접기·펼치기를 연결하고 해당 단계 바로 아래 설명을 제공한다. 상단 위치 표시와 본문 상세 탐색의 역할을 구분한다. |

### 3.1 범위 문구는 위치뿐 아니라 분기도 복원

현재 건강보험 확인 결과 R08/R10과 의료급여 R05에도 똑같은 기본 흐름 문구가 표시된다. 원본은 건강보험 확인 결과에서 이 미확인용 문구를 생략하고, 의료급여 결과에는 구입 전 주민센터의 별도 신청·승인/청구 절차를 확인하는 문구를 사용한다(Handoff §4.1). 위치를 옮기면서 원본 조건도 함께 복원해야 한다.

### 3.2 색상 통일은 상태 의미의 통합을 뜻하지 않음

검정/노랑이 무작위로 섞인 것은 아니며, 관찰한 화면에서는 진행과 미확인에 대응한다. 제작자의 의도나 소스 분기까지 직접 확인한 것은 아니다. 같은 연노랑 계열로 강조하더라도 ‘검사·진단 중’, ‘등록 진행 상태 확인 필요’처럼 명시한다. 이미 확인된 단계는 체크와 문구, 이후 단계는 읽을 수 있는 일반 글자로 구분한다. 모든 미확인에 특정 현재 단계 색을 강제로 지정하지 않는다.

임시 색 제안: ‘지금 할 일’에는 은은한 연노랑 면과 짙은 본문, 과정의 현재 위치에는 같은 계열의 표식/테두리. 미래 단계는 연한 회색 글자로 비활성처럼 만들지 않는다. 검정은 본문·제목에 사용한다. 최종 브랜드 색 확정 이후에도 의미 체계는 유지한다.

### 3.3 답변 비교가 쉬운 인라인 결과

권장 읽기 흐름: 간결한 전체 과정 표시 → 현재/마지막 질문과 선택지 → 결과 요약 → 절차 안내 → 강조된 지금 할 일 → 상담 질문 → 선택형 상세.

- 모든 과거 질문의 선택지를 한꺼번에 쌓을 필요는 없다. 앞 질문은 요약하고, **결과를 만든 질문**은 펼친 채 유지한다. 예를 들어 Q1에서 끝나는 검사 중 결과는 Q1 선택지를, Q4에서 끝나는 결과는 Q4 선택지를 유지한다.
- 첫 결과는 해당 질문 바로 아래에 등장한다. 결과 영역 첫머리로 이동하면서 제목에 초점을 준다. 맨 아래 ‘지금 할 일’까지 자동으로 건너뛰면 다시 선택지를 찾기 어려워진다.
- 같은 질문의 다른 답을 선택하면 이전 결과를 누적하지 않고 같은 자리에 갱신한다. 앞 답을 변경하면 영향을 받는 뒤 답·결과·복사문·상세 열림 상태도 원본 규칙대로 처리한다.
- 반복 비교 때 불필요하게 화면이 길게 움직이지 않도록 한다. 동작 줄이기 설정에서는 애니메이션을 강제하지 않는다.

### 3.4 단계 탐색은 ‘현재 위치’를 변경하지 않음

본문의 단계 카드 자체를 누르면 설명이 펼쳐지게 하면 별도 ‘보기’ 버튼 다섯 개를 늘리지 않아도 된다. 펼침 표시와 키보드 조작, 열림 상태 전달은 필요하다. 단계 이름만으로 조작 가능 여부를 숨기지 않는다.

- 각 단계에 ‘어디에서 / 무엇을 / 언제’를 짧게 제공한다. 자세한 비용·서류·공식 근거는 기존 상세를 연결한다.
- 검수·청구 또는 이후 관리를 펼쳤다고 설문 결과·현재 위치·완료 상태가 바뀌면 안 된다. 현재 위치의 강조는 답변 기준으로 남기고, 열어 둔 설명은 ‘펼친 안내’ 및 방향 표시 등으로 구분한다.
- 보험 미확인/의료급여에서도 일반 설명을 살펴볼 수는 있으나 건강보험 절차를 개인별 확정 경로처럼 보여주지 않는다. 적용 범위와 기관 분기를 유지한다. 공통 상세를 펼친 사실로 개인 지원액을 새롭게 계산하거나 노출하지 않는다.
- 단계 탐색은 **기존 수동 과정 표시에서 달라지는 제안**이다. 승인되면 Handoff의 ‘탐색 버튼 묶음이 아닌 표시’ 원칙과 관련 검토 기준을 수정한다. 현재 문서를 승인 없이 새 기능 명세로 바꾸지 않는다.

## 4. 추가 발견 사항

1. **데스크톱과 모바일의 정보량이 다르다.** 본문 과정 표시의 데스크톱 요소는 단계명·상태만 있고, 모바일 요소에는 기관과 일부 설명이 있다. DOM에도 별도 요소(`hidden sm:flex`, `flex flex-col sm:hidden`)로 구성되어 있다. 화면 폭에 따라 안내 내용을 누락시키지 않도록 같은 데이터를 사용해야 한다.
2. **미래 단계가 지나치게 작고 흐리다.** 상단 단계명은 10px, 상태는 9px이며 미래 단계에는 `#C8C5BF`/`#D0CEC9` 같은 연한 글자를 사용한다. 320px에서는 라벨이 좁게 줄바꿈된다. 넘침이 없다는 것만으로 읽기 문제가 해결되지는 않는다. 새 단계 탐색을 제공할 때 비활성처럼 보이는 표현부터 바꾼다.
3. **상단과 본문이 비슷한 단계 막대를 반복한다.** 상단은 짧은 위치 지도, 본문은 기관·행동과 선택형 설명으로 역할을 나누면 중복을 줄일 수 있다. 등록 내부 4단계도 대표 검사 중 결과에서 여전히 보이지 않았다.
4. **일부 기관 표기 축약이 원본과 다르다.** R12 모바일 검수·청구는 ‘이비인후과 / 국민건강보험공단’으로 표시되어 위임 청구의 판매업소와 보험 미확인 범위가 빠져 있다. 단계 상세 작성 시 원본의 자격별 기관 문구를 재사용해야 한다.
5. **설문 소개의 보호자 응답 기준 문구가 보이지 않는다.** 원본의 ‘보청기를 사용할 분의 등록 상태와 보험 자격을 기준으로 답해 주세요’는 보호자 기능을 연결할 때 복원할 필요가 있다.
6. **예정된 2단계와 회귀를 구분한다.** R03/R04/R05/R10/R12에는 상담 질문·상세 문의가 2단계 예정으로 표시된다. 이를 이번 1단계의 무작위 누락이라고 해석하지 않는다. 사용자에게 최종 공개할 때는 작업 단계 문구를 제거하고 실제 내용을 완성해야 한다.

## 5. 권장 우선순위

1. 결과를 만든 질문 유지 + 같은 영역에서 결과 갱신: 사용자가 직접 제기한 비교 탐색 문제부터 해결.
2. 범위 문구 위치/분기, 지금 할 일 강조, 미래 단계 글자 가독성: 작은 변경으로 핵심 행동을 명확하게 함.
3. 본문 단계별 펼침: 남은 2단계 콘텐츠를 같은 구조로 연결하며 현재 위치와 탐색 상태를 분리.
4. 비용·보호자·제품·왕복·복사 등 예정된 2단계 기능 및 전체 분기/접근성 회귀 확인.

본 문서 작성 외 로컬 앱 코드, Figma, 게시 상태는 변경하지 않았다.
