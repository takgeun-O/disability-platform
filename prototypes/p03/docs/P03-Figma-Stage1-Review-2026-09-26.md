# P03 Figma Make 1단계 검토 및 후속 요청

## 1. 확인 대상과 결론

- 실제 확인 대상은 [기존 Make 프로젝트](https://www.figma.com/make/3BOg49ITxCde7KQ0lakmXx/Desktop-Homepage-Wireframe?p=f&t=UyuOEh9CXKaci7Cz-0)의 **버전 47 미리보기**다. 미리보기 내부 경로 `/validation/hearing-aid-health-insurance`에서 설문을 조작했다.
- [기존 공개 사이트의 같은 경로](https://ochre-bead-10600476.figma.site/validation/hearing-aid-health-insurance)는 확인 당시 **‘준비 중입니다.’**였다. 공개 사이트에서 새 통합본을 검증했다고 해석하지 않는다.
- 15개 결과 경로를 실제 선택한 결과, **‘전체 절차와 내 위치’는 R02와 R08에서만 표시되고 다른 13개 결과에서는 표시되지 않았다.** 질문에 답하는 동안의 상단 공통 과정 표시도 없었다.
- 최초 1단계 요청 자체가 대표 결과 R02/R08 중심이었다. 다른 13개 결과의 질문·복사·상세가 미완성인 것은 보고된 단계 구분과 일치한다. 이를 모두 예기치 않은 오류로 취급하지 않는다. 다만 모든 분기에서 전체 과정과 현재 위치를 파악하게 하려면, 공통 과정 표시를 대표 결과 전용 구현과 분리해 먼저 보완하는 것이 좋다.
- Make 소스 파일은 직접 읽지 않았다. 아래는 브라우저 관찰과 원본 로컬 코드의 대조다. 특정 조건문이나 CSS를 누락 원인으로 확정하지 않는다.

## 3. 우선 보완 사항

### A. 질문 중에도 공통 5단계를 볼 수 있어야 한다

**재현:** 시작 → 내 상황 확인하기 → Q1부터 Q4까지 진행.

**기대:** Handoff §4.1·§8과 원본 `VisitOverview.tsx` / `GuidedCheck.tsx`처럼 질문 상단에 `등록 확인 → 병원 처방 → 구입·착용 → 검수·청구 → 이후 관리`를 표시한다.

**실제:** 질문들만 이어지고 상단 과정 표시가 없다. 결과 안의 5단계는 R02/R08에서만 뒤늦게 보인다.

**영향:** 전체 과정을 모르는 사람이 질문의 목적과 현재 확인하는 주제를 연결하기 어렵다.

**요청:** 질문·결과 공통 영역에 작은 과정 표시를 둔다. Q1은 등록, Q3은 처방에 해당하는 질문 주제를 강조한다. Q2 보험 자격·Q4 지원 이력은 특정 단계 완료를 뜻하지 않는다. 결과가 나오면 질문 주제 대신 답변 기반 상태를 표시한다. 색 외에 문구로도 의미를 구분한다. 단계별 이동 버튼을 추가할 필요는 없다.

### B. 모든 결과에 같은 절차 안내 구조를 사용한다

**재현:** R02에서 Q1을 심사 대기(R03)로 변경하거나, R08에서 Q4를 이력 있음/모름(R09/R10)으로 변경.

**실제:** 상태와 다음 행동은 바뀌지만 전체 절차 영역 자체가 사라진다.

**영향:** 특정 선택지만 유효한 진행 경로처럼 보이고, ‘모름’을 선택한 사용자는 오히려 큰 그림을 잃는다.

**요청:** 상세 질문·비용을 2단계에 남기더라도, 모든 결과가 공통 절차 영역을 사용하도록 보완한다. 현재 상태·답변 사실·미확인 항목·단계 라벨은 Handoff의 각 결과 데이터와 연결한다. 결과 번호로 영역의 유무를 결정하지 않는다.

‘항상 표시’는 ‘항상 어느 한 단계를 현재로 칠한다’는 뜻이 아니다. R05, R09–R15의 상단은 단일 현재 단계 강조 없이 확인 필요 내용을 표시한다. 하단 상세 여정에서는 이미 확인된 사실과 미확인을 구분한다. 모름을 건강보험·첫 지원·구입 가능으로 바꾸지 않는다. 의료급여는 별도 사전 절차와 기관 표기를 유지한다.

### C. 대표 결과에서도 기관과 단계 설명을 복원한다

**재현:** R02 또는 R08 → 전체 절차와 내 위치.

**기대:** Handoff §4.1 및 원본 `ResultJourney.tsx`: 각 단계에 상태, 담당 기관, 한 문장 설명. 등록 전 결과에는 등록 내부 흐름도 제공.

**실제:** 5개 단계명과 상태 라벨은 있지만 기관·설명 문장이 없다. R02에 검사·진단 → 주민센터 제출 → 심사 → 결과 확인 흐름도 없다.

**영향:** ‘병원 처방’이나 ‘검수·청구’라는 이름만으로는 어디에서 무엇을 하는지 이해하기 어렵다. 특히 검사 중인 사람이 등록이 완료되는 과정을 알 수 없다.

**요청:** 상단은 짧은 과정 표시, 결과 본문은 기관·행동을 설명하는 여정으로 역할을 나눈다. 같은 긴 설명을 두 곳에 반복하지 않는다. R02의 등록 내부 흐름에서 검사·진단을 ‘지금’으로 표시한다. 좁은 화면은 상세 여정을 세로로 쌓되, 고정 상단 영역 전체가 화면을 채우지 않게 한다.

## 4. 함께 확인한 차이와 선택적 정리

- **다시 시작 목적지:** Make의 ‘처음부터 확인하기’는 요약으로 돌아간다. 원본 `FocusedFlow.tsx`의 `restart()`는 답변을 비우고 첫 질문으로 이동한다. 기존 기능 보존을 위해 첫 질문 및 제목 초점으로 맞추는 것을 권장한다.
- **질문 누적:** Make에서는 Q1–Q4 질문과 모든 선택지가 계속 쌓인다. 원본은 현재 질문 또는 결과를 만든 마지막 질문을 남기고 ‘이전 질문’으로 돌아간다. 현재 방식은 결과까지 읽어야 할 길이를 늘린다. 원본 방식 복원 또는 이전 답변을 짧게 요약하는 디자인을 권장하되, 접기·수정 버튼을 여러 개 추가하지 않는다. 이는 주요 과정 표시 누락과 구분되는 디자인 조정이다.
- **개발용 표기:** 실제 화면에 `확인 결과 · R02` 같은 번호가 보인다. Handoff §4에서 번호는 비교용이라고 명시했다. 사용자용 화면에서는 빼고, ‘2단계에서 구현’ 등 작업 상태는 검토용 보고로 분리한다. 미구현 기능을 완성된 것처럼 꾸미라는 뜻은 아니다.
- **질문 영역 제목:** 대표 결과에서 ‘병원·센터에서 물어볼 질문’으로 표시하지만 내용은 기존 센터 질문 3개다. 개인별 결과의 ‘센터에서 물어볼 질문 3개’와 보호자 공통 안내의 병원·센터 질문을 구분한다.
- **R08의 범위 설명:** 건강보험이라고 답했는데도 ‘보험 자격에 따라 … 달라질 수 있어요’라는 미확인용 설명이 표시된다. 원본 `ResultJourney.tsx`는 건강보험 확인 결과에 이 설명을 표시하지 않는다. 공통 여정을 만들 때 모든 결과에 같은 범위 문구를 하드코딩하지 않는다.

## 5. 이번 확인 범위와 한계

확인한 것:

- Make v47 시작 화면, Q1–Q4, 15개 결과의 실제 진입과 절차 영역 유무.
- Q1에서 바로 끝나는 경로, 의료급여의 Q2 종료, 처방전 없음/모름의 Q3 종료.
- Q4 처음/있음/모름 변경 시 결과가 달라짐. Q2 변경 시 기존 Q3/Q4 결과가 제거됨.
- 미확인 보험 결과 표본 전체에서 건강보험 지원율·금액이 표시되지 않음. 다만 이 결과의 상세 구현이 아직 없으므로 완성된 B02 검증으로 간주하지 않음.
- R08 ‘지금 할 일 보기 ↓’를 Enter로 작동했을 때 `h3#today-tasks`로 초점이 이동하고 스크롤 종료 후 제목이 미리보기 상단 안에 나타남.
- ‘처음부터 확인하기’가 요약 화면으로 이동함.
- 원본 `GuidedCheck.tsx`, `VisitOverview.tsx`, `ResultJourney.tsx`, `FocusedFlow.tsx`와 전달 문서 대조.

미확인:

- Make 소스 내부 원인, 서버 전송·저장 여부, 복사 성공/실패와 실제 클립보드 내용.
- 320px/390px 및 실물 모바일, 전체 Tab/Space 순서, 화면낭독기, 동작 줄이기 설정.
- 제품 선택·참고/보호자 왕복·전체 비용 카드·다른 13개 결과의 상세. 모두 2단계 예정 영역이다.
- 이번 검토에서 홈/복지 연결 전체를 다시 검증하지 않았다. 이전 원본 조사와 이번 통합본 검증을 혼동하지 않는다.

앱 코드와 Figma는 수정하지 않았고 커밋·푸시·배포도 하지 않았다. 검토 문서만 추가했으며 테스트·빌드를 실행하지 않았다.

## 6. Figma Make에 붙여 넣을 보완 요청

아래 요청은 2단계 전체 구현 전에 공통 안내 구조를 보완하는 범위다. 원본 Handoff를 계속 참고한다. 이 보완만으로 2단계가 완료되는 것은 아니다.

```text
1단계 미리보기를 검토했습니다. 전체 디자인 방향은 유지하되, 2단계 상세 구현 전에 ‘전체 과정과 내 위치’를 일관되게 볼 수 있도록 공통 구조부터 보완해 주세요.

현재 v47에서는 ‘전체 절차와 내 위치’가 R02/R08에만 나오고 다른 13개 결과에는 없습니다. 질문을 답하는 동안 상단 과정 표시도 없습니다. 다른 결과의 상세를 2단계로 미룬 것은 이해하지만, 전체 과정과 현재 위치는 어느 선택지에서든 참고할 수 있어야 합니다.

1. 질문·결과 상단의 공통 과정 표시
- 등록 확인 → 병원 처방 → 구입·착용 → 검수·청구 → 이후 관리의 5단계를 항상 보여 주세요.
- 질문 중 Q1은 등록, Q3은 처방을 ‘지금 확인하는 주제’로 표시합니다. Q2 보험 자격·Q4 지원 이력을 특정 단계 완료로 표현하지 마세요.
- 결과가 나오면 답변에 따른 상태로 갱신합니다. R05/R09–R15는 억지로 한 단계를 현재로 지정하지 말고 확인 필요 문구를 표시합니다.
- 스크롤 위치를 사용자의 실제 현재 상태로 바꾸지 마세요. 단계 그림에 불필요한 버튼을 추가하지 마세요.
- 작은 화면에서는 간결하게 배치하고, 고정 영역 때문에 질문·제목이 가려지지 않게 해주세요.

2. 모든 결과에서 공통 ‘전체 절차와 내 위치’ 제공
- R02/R08만 별도 완성 레이아웃을 쓰지 말고 모든 15개 결과에 같은 구조를 적용해 주세요.
- 상태 요약 → 다음 행동 한 줄/빠른 이동 → 답변 사실 → 전체 절차와 내 위치 → 지금 할 일 → 센터 질문 → 선택형 상세라는 원본 순서를 기준으로 합니다.
- 이번 보완에서는 모든 결과의 상태·다음 행동·답변 사실·여정까지 공통으로 연결하고, 아직 구현하지 않은 상담 질문·비용·보호자·제품 등의 상세는 기존 2단계 범위로 남겨도 됩니다. 미구현 내용을 임의 생성하지 마세요.
- Handoff §4.1 및 §11의 각 결과별 완료/현재/확인 필요/이후 과정 라벨을 사용합니다. 모름을 아니오·첫 지원·건강보험 확인으로 바꾸지 마세요.
- 의료급여와 보험 미확인의 기관·범위 문구를 구분합니다. 보험 미확인 결과에 지원율·지급액을 개인 적용처럼 표시하지 마세요.

3. 단계 이름만으로 설명을 대체하지 않기
- 결과 본문의 각 단계에는 Handoff §4.1 원문의 기관과 한 문장 설명을 유지해 주세요. 상단 표시에는 긴 설명을 반복하지 않습니다.
- 등록 전/검사 중/심사 대기/등록 상태 모름에는 검사·진단 → 등록 신청·자료 제출 → 장애정도 심사 → 등록 결과 확인 흐름을 유지합니다.
```
