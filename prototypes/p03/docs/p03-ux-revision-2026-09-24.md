# P03 결과 구조·미확인 분기 개선 — 2026-09-24

사용자 요청에 따라 배포 화면을 직접 확인하고 로컬 Next.js 구현을 수정했다. 이 작업은 구현·검증이며 커밋·푸시·배포·Notion 변경은 수행하지 않았다. 배포 화면은 비교 대상으로만 사용했다.

## 결과 구조

모든 결과를 **현재 상태 → 전체 절차 속 내 위치 → 지금 할 일 → 센터 질문 3개 → 선택형 상세** 순서로 구성했다.

- 답변한 사실만 상태로 정리한다. 등록 완료와 처방전 수령은 명시적으로 답했을 때만 완료로 표시하며, 구입·검수·관리를 완료했다고 추론하지 않는다.
- 기존 5단계에 기관과 역할 한 문장을 붙였다. 등록 전에는 검사·진단 → 등록 신청 → 심사 → 결과 확인을 첫 단계 안에 표시한다. 신청 전 주민센터에 안내받는 경로도 남겼다.
- 고정 그림은 질문 중에는 질문 주제, 결과에서는 응답에 따른 상태를 표시한다. 스크롤로 읽는 위치를 감지하던 코드는 제거했다. 보험 자격·이전 지원 이력 확인은 특정 단계의 진행으로 단정하지 않는다.
- 다음 행동은 기관·방법·그대로 전달할 문의 문장으로 구성했다. 센터의 상담·도움 범위는 기관에 확인할 행동과 구분했다.
- 센터 질문은 상황별 3개와 각 질문의 확인 목적을 제공한다. 현재 상태와 문의 문장, 질문·목적을 함께 복사한다.
- 건강보험의 마지막 결과에서만 후속 절차, 비용·지급 조건, 직접 청구 자료를 각각 접어서 표시한다. 여러 시점의 지원을 합한 금액이며 일시 지급이 아니라는 요약은 남겼다. 등록 전·보험 미확인·의료급여 결과에 건강보험 금액을 확정해 보여주지 않는다.
- 제품 조회는 선택형 보조 기능을 유지했다. 답변은 기존처럼 컴포넌트 메모리에만 유지한다.

## 대표 시나리오 비교

| 상황 | 배포 화면에서 확인한 문제 | 로컬 변경 |
| --- | --- | --- |
| 검사·진단 중 / 심사 대기 | 짧은 단계명만으로 기관별 역할·다음 순서를 알기 어려움 | 결과에 전체 흐름과 등록 내부 위치, 병원/주민센터에 할 문의를 직접 표시 |
| 등록 완료 + 보험 자격 모름 | 즉시 결과로 종료하고 등록 확인을 강조 | 처방 질문과 해당하는 지원 이력 질문을 계속 진행. 보험 자격은 끝까지 미확인으로 유지 |
| 처방 여부 모름 | 질문과 설명의 처방 용어가 달라 혼란 | ‘지원금 신청용 보청기 처방전’으로 통일. 공식 명칭과 진단서·단순 권유와의 차이를 짧게 설명 |
| 이전 지원 이력 모름 | 구입·착용 강조가 구입 가능한 상태로 읽힐 수 있음 | 별도 ‘이전 지원 이력 확인 필요’ 상태와 공단에 물어볼 문장 제공 |
| 건강보험 + 첫 지원 | 펼쳐진 비용·후속 절차 때문에 상담 질문이 뒤로 밀림 | 질문 3개를 먼저 표시하고 비용·서류는 개별 펼쳐보기로 이동 |
| 결과 아래로 스크롤 | 읽는 안내에 따라 현재 단계 강조가 바뀜 | 응답에 따른 현재 상태를 유지 |

## 주요 파일

모든 경로는 `frontend/` 기준이다.

- `src/app/validation/hearing-aid-health-insurance/guided-content.ts`: 질문, 15개 결과 분기, 사실/미확인 상태, 단계 상태, 이후 답변 초기화 함수.
- `GuidedCheck.tsx`: 결과 순서, 초점 이동, 기관 문의 안내, 질문과 상세 연결.
- `ResultJourney.tsx`, `RegistrationSequence.tsx`: 기관별 5단계와 등록 내부 흐름. 등록 흐름은 참고 화면과 공유.
- `VisitOverview.tsx`: 질문 주제와 결과 상태를 구분하는 고정 그림. `useReadingPhase.ts`, `reading-position.ts`는 삭제.
- `consultation-content.ts`, `question-note.ts`, `QuestionTakeaway.tsx`: 상황별 질문과 목적, 상태를 포함한 복사문, 성공·실패 안내.
- `AfterPurchaseGuide.tsx`, `ClaimDocuments.tsx`: 분리된 선택형 상세와 공유 서류 안내. 비용은 기존 `BenefitBreakdown.tsx`를 재사용.
- `ReferenceGuide.tsx`, `RegistrationHelp.tsx`, `content.ts`: 쉬운 용어·단계 설명의 일관성, 공식 온라인 상담 출처.
- `page.module.css`: 결과의 상태·기관·문의 영역, 좁은 화면의 등록 순서와 줄바꿈.
- `scripts/check-visit-flow.mjs`: 분기, 미확인 상태, 완료 추론 방지, 답변 변경, 복사문 회귀 검사.

## 공식 자료 확인 범위

확인일: 2026-09-24. 기존 지원액·지원 비율·자격 조건과 제품 데이터는 이번 UX 작업으로 변경하지 않았다.

1. [보건복지부 장애인등록·장애정도 심사](https://www.mohw.go.kr/menu.es?mid=a10710010900): 주민센터 안내·신청, 의사의 검사·진단 자료, 국민연금공단 심사와 결과 안내를 확인했다. 먼저 진단 자료를 갖춘 뒤 신청하는 경우도 있어 주민센터 방문을 모든 경우의 절대적인 선행 조건으로 만들지 않았다.
2. [국민건강보험법 시행규칙 제26조](https://www.nhis.or.kr/lm/lmxsrv/law/lawFullContent.do?SEQ=29): 지원 신청 서류의 공식 명칭 ‘보조기기 처방전’과 검수확인서·청구 근거를 확인했다. UI의 쉬운 명칭과 공식 명칭을 구분한다.
3. [장애인보조기기 보험급여 기준 등 세부사항](https://www.nhis.or.kr/lm/lmxsrv/law/lawFullContent.do?SEQ=87&SEQ_HISTORY=613408): 기존 후기 관리·별도 청구 설명을 대조했다. 비용 표의 세부 근거와 이전 원문 검증은 [기준 재조사 기록](reference-review-2026-09-24.md)을 따른다.
4. [보건복지부 의료급여 안내](https://www.mohw.go.kr/menu.es?mid=a10708030100): Q2의 짧은 제도 설명을 확인했다. 건강보험의 금액·청구 순서를 의료급여에 그대로 적용하지 않는다.
5. [공단 온라인 개인 상담](https://www.nhis.or.kr/nhis/minwon/retrieveCvaplCstInfoColctAgreView.do): 공단 홈페이지 ‘국민소통·참여 → 온라인 상담문의 → 개인 상담’ 메뉴와 로그인 진입을 확인했다. 사용자의 로그인이나 실제 상담 신청은 하지 않았다. 개인 자격·지원 기록을 바로 조회하는 화면으로 설명하지 않으며, 공식 온라인 문의 경로로만 제공한다. 확인되지 않은 문자 상담 채널은 추가하지 않았다.

## 검증

### 자동 검사

최종 소스로 다음 명령을 실행했으며 모두 통과했다. 프로덕션 빌드에서 대상 경로가 정적 페이지로 정상 생성됐다.

```sh
npm run lint
npm run typecheck
npm run test:visit-flow
npm run test:products
npm run build
```

`test:visit-flow`는 도달 가능한 15개 결과, 보험 미확인 상태의 후속 질문, 응답에 근거한 완료 표시, 건강보험 상세 노출 조건, 이전 답변 수정 시 이후 응답 제거, 상태·질문·목적의 복사문, 제품 선택 반영을 검사한다. 제품 검사는 기존 206개 제품 목록과 검색·가격·최신성 분기를 확인한다.

### 실제 브라우저

- 등록 전 4개 결과(검사·신청 전, 검사·진단 중, 심사 대기, 상태 모름), 의료급여 결과, 건강보험 5개 결과, 보험 자격 미확인 5개 결과를 모두 선택지 클릭으로 확인했다.
- 보험 자격 모름 → 처방 완료 → 각 지원 이력 응답에서도 보험 미확인을 유지하고 건강보험 비용 상세가 나타나지 않았다.
- 이전 질문으로 돌아가 답변을 바꾸면 이후 응답·결과가 제거됐다. 참고 화면을 왕복하면 응답·결과·선택 제품이 유지됐다.
- Q4 첫 지원 결과의 질문 3개가 상세보다 먼저 나오고 비용 표가 처음에는 접혀 있음을 확인했다. 상세를 읽어도 현재 상태 강조가 바뀌지 않았다.
- 제품코드 `D22018010015`를 검색·선택하고 추천 질문에 모델이 반영되는 것을 확인했다.
- 키보드 Enter로 선택지·펼쳐보기를 조작하고, 응답 후 질문/결과 제목에 초점이 이동하는 것을 확인했다. 실패 시 복사 영역에서도 Tab으로 다음 요소로 이동할 수 있었다.
- 실제 복사 버튼의 성공 안내를 확인했다. 로컬 QA 탭에서 Clipboard API 전달값을 일시적으로 관찰해 현재 상태·처방·질문 3개·목적이 포함됨을 확인하고, 권한 오류를 모사해 수동 복사 영역과 실패 안내를 확인했다. 이후 임시 관찰/오류 설정은 원상 복구했다. IAB 클립보드 도구와 페이지 Clipboard API가 분리되어 외부 앱에 실제 붙여넣기는 검증하지 않았다.
- 1280px 데스크톱, 390px·320px 모바일 폭에서 대표 결과·등록 흐름·비용 표를 시각 확인했다. 가로 넘침이 없고 고정 그림이 결과 제목을 가리지 않았다. 800×400에서는 고정이 해제됐다.
- 검증 종료 시 브라우저 콘솔 오류·경고가 없었다.

## 남은 검증과 범위

- 실제 사용자에게 절차 이해도를 검증하거나 실제 화면낭독기로 전체 흐름을 확인하지는 않았다. 이 기록은 구현 검증이며 사용자 Evidence가 아니다.
- 공단 개인 상담은 공개 메뉴와 로그인 경로까지만 확인했다. 로그인 이후 제출·답변과 개인별 지원 자격은 확인하지 않았다.
- 의료급여의 개인별 사전 승인과 지원 적용은 주민센터 확인을 유지한다. 기존 C01–C04 전체나 모든 행정 예외를 해결했다고 기록하지 않는다.
- 새 저장·답변 전송·공단 API·외부 연락·배포는 없다.
