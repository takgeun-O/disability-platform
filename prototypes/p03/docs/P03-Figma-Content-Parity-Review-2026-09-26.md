# P03 UX 보완 게시본 — 원본 결과 콘텐츠 대조

확인일: 2026-09-26. 대상은 [수정된 Figma 게시본](https://ochre-bead-10600476.figma.site/validation/hearing-aid-health-insurance)과 [기존 P03 게시본](https://iyum-validation.vercel.app/validation/hearing-aid-health-insurance)이다. 두 사이트에서 같은 답변으로 **R01–R15 전체 결과**에 실제 진입해 ‘지금 할 일’과 센터 질문 영역을 대조했다. Make 소스 버전 번호는 확인하지 않았다.

기준: [Handoff](./P03-Figma-Handoff.md) §4–5·§10–11, [직전 UX 보완 요청](./P03-Figma-UX-Refinement-Prompt.md), 로컬 `guided-content.ts`, `GuidedCheck.tsx`, `content.ts`.

## 1. 결론과 범위 해석

**공통 UX는 개선됐지만 결과 콘텐츠 이관은 대표 2개에 머물러 있다.** 13개 결과에서 ‘이렇게 물어보세요’와 ‘센터 상담에서 도움받을 일’이 누락되었고, 센터 질문 3개도 ‘2단계에서 구현’으로 남았다. 원본은 15개 모두에 이 내용을 제공한다.

앞선 요청은 대표 결과 중심의 1단계와 공통 UX 보완을 진행하면서, 나머지 문의·상담 질문 상세를 2단계 잔여로 허용했다. 따라서 13개 상세의 부재는 모든 내용을 옮기다가 갑자기 삭제한 것으로 단정할 일이 아니라 **아직 이관하지 않은 콘텐츠**로 보는 것이 정확하다. 사용자에게는 필요한 설명이 없는 상태이므로, 다음 작업의 우선순위는 결과 콘텐츠 이관이다.

별도로 이번 수정에서 **상단 다음 행동 문장이 기관명만 남은 문제**와 **보험 미확인 결과의 단계 펼침에서 금액이 노출되는 문제**를 확인했다. 이 둘은 예정된 콘텐츠 미완성과 구분해서 수정해야 한다.

## 3. 실제 누락 예시와 사용자 영향

### 등록 시작 전(R01)

현재: ‘방문해서 청각장애 등록 신청 방법과 진단받을 병원을 안내받으세요.’

원본에 있고 현재 빠진 문의 문장:

> 청각장애 등록을 처음 알아보고 있어요. 어떤 병원에서 검사받고, 검사 후에는 어디에 자료를 내면 되나요?

원본은 이어서 센터에서 청취 불편·제품 상담은 가능하지만 실제 구입은 등록·처방과 지원 절차를 확인한 뒤 결정하도록 설명한다. 기관을 알려주는 것과 실제로 어떤 말을 꺼낼지 준비해 주는 것은 다르다.

### 등록 상태 모름(R04)

현재: ‘방문해서 등록 신청 기록과 결과가 있는지 확인하세요.’

빠진 문의 문장:

> 제가 청각장애 등록을 신청한 기록이 있나요? 심사 중인지, 등록이 완료됐는지와 다음에 제가 할 일을 확인해 주세요.

추가로 ‘신청 기록이 없고 병원 검사만 받았다면, 그 병원에서 장애등록용 검사였는지 확인하세요.’와 현재 아는 검사·진료 내용으로 센터에서 상담할 수 있다는 설명도 빠졌다. 모르는 상태에서 확인 결과에 따라 다음 행동으로 연결해 주던 부분이다.

### 이전 지원 이력 모름(R10)

현재: ‘온라인 개인 상담이나 지사 방문으로 이전 보청기 지원 기록이 있는지부터 확인하세요.’

빠진 문의 문장:

> 이전에 보청기 건강보험 지원을 받은 기록이 있는지 확인해 주세요. 기록이 있다면 지원받은 날짜와 이번 신청 전에 확인할 조건을 알려주세요.

원본에는 공단 온라인 상담 링크와 ‘국민소통·참여 → 온라인 상담문의 → 개인 상담’ 경로, 전화 대신 글로 문의할 수 있다는 설명이 있다. 현재는 온라인 상담을 언급하면서 실제 이동 수단을 제공하지 않는다. 링크 복원 시 원본의 로그인·새 탭 안내도 유지한다.

### 보험과 처방전 모두 모름(R12)

현재는 ‘보험 자격에 따라 처방전 확인 방법이 달라져요’라고 끝난다. 원본은 공단에 자격을 물어볼 문장과 함께, 받은 처방전 여부는 진료받은 병원에 **‘지원금 신청용 보청기 처방전을 발급받았나요?’**라고 확인하도록 구체적으로 안내한다. 자격 확인 중에도 센터 상담은 가능하며 지원액·구입 시점은 자격 확인 후 정한다는 설명도 빠졌다.

새로운 행정 설명을 늘릴 필요는 없다. Handoff §11에 이미 있는 결과별 `action.ask`, `action.online`, `secondary`, `center`와 상담 질문을 그대로 이관하는 것이 우선이다.

## 4. 별도로 수정할 문제

### P1. 보험 미확인 결과의 이후 관리에서 금액 노출

- 재현: 등록 완료 → 보험 모름 → 처방전 받음 → 기억나지 않아요(R15) → 본문 ‘이후 관리’를 Space로 펼침.
- 실제: ‘연 1회 이상 실제 관리를 받은 뒤 후기 적합관리비(연 5만 원)를 청구할 수 있어요.’
- 기대: 이 결과의 단계 열람으로 건강보험 지원율·지급액을 새로 노출하지 않는 합의(직전 보완 요청 §5). 실제 지급액과 공통 계산 기준을 혼동하지 않아야 한다.
- 영향: 보험 자격이 미확인인데 본인에게 연 5만 원이 지급되는 것처럼 읽힐 수 있다. 원본 R15에는 해당 개인용 비용 상세 자체가 없다.
- 요청: 미확인/의료급여의 단계 설명은 자격에 맞는 관리·절차 확인 안내로 제한한다. 일반 건강보험 금액은 명시적인 공통 기준 안내에서만 기존 조건·최대·계산 기준을 포함해 제공한다. R11–R15 및 의료급여에서 새 펼침 경로 전체를 점검한다. 이 검토에서 직접 금액 노출을 재현한 경로는 R15다.

### P2. 결과 상단의 ‘다음 행동 한 줄’ 소실

- 결과 상단이 ‘국민건강보험공단 [지금 할 일 보기 ↓]’ 같은 형태로 기관명만 표시된다. DOM에도 행동 문장이 없다.
- 원본은 `다음 행동: 기관 · action.instruction`이며, 상세 ‘지금 할 일’과 같은 데이터를 쓴다.
- 상세를 읽거나 버튼을 누르기 전에 무엇부터 할지 알 수 있도록 행동 한 줄을 복원한다. 상세 문의 문장 전체를 상단에 반복할 필요는 없다.

### P2. 미확인 단계 표시와 조건부 문구를 다시 대조

- R15 상단은 구입·착용 칸을 노란색으로 강조하면서 ‘보험 자격 확인 필요’를 넣는다. 합의는 이 결과에서 특정 현재 단계 하나를 확정하지 않고 별도 확인 필요 문구를 표시하는 것이다. 상단 지도와 본문 단계 상태를 같은 방식으로 처리하지 않도록 한다.
- 보험 모름 이후 질문에서 원본의 ‘보험 자격은 미확인으로 유지하고 있어요’ 안내가 빠져 있다. 질문을 계속한다고 자격이 확인된 것으로 보이지 않게 유지한다.
- R11/R12/R14/R15의 행동 문장이 원본과 달라졌다. 특히 ‘건강보험이면 … 처방전을 받을 수 있어요’ 등의 새 확정성 표현을 덧붙이기보다 검증된 원본 문구를 복원한다.

## 5. UX 보완 결과

| 항목 | 이번 확인 |
| --- | --- |
| 결과를 만든 마지막 질문·선택지 유지 | 확인. 같은 질문의 다른 답으로 결과가 갱신되고 변경 알림도 있음 |
| 앞 답 변경과 후속 답·상세 초기화 | 표본에서 확인. 열린 단계 상세도 새 결과에서 접힘 |
| 범위 문구 위치 | 본문 단계 안내 위로 이동함 |
| 지금 할 일 강조 | 연노랑 카드·짙은 글자 적용. 내용이 비어 있는 문제와 구분 |
| 단계별 펼침 | native details/summary. R15 검수·청구 Enter, 이후 관리 Space로 열림. 해당 열람으로 상단 상태가 바뀌지 않음 |
| 자격별 기관 표시 | 보험 미확인 검수·청구에 ‘건강보험 청구: 판매업소 위임 또는 국민건강보험공단’ 표기가 복원됨 |
| 보호자 응답 기준 | 소개에 복원됨 |
| 빠른 이동 | R15에서 ‘지금 할 일 보기’ Enter 후 제목 초점 도달, 이동 후 제목 화면 안에 표시 |
| 복사 | R08 복사 성공 안내 및 실제 클립보드의 현재 상태·문의·질문 3개 확인. 다른 13개에는 아직 해당 기능이 없음 |
| 반응형 | 수정본의 실제 DOM 폭 390/320px에서 관찰한 상태의 가로 넘침 없음. 모바일 전체 시각·접근성 통과를 뜻하지 않음 |
| 데스크톱/모바일 정보 일치 | 본문이 공통 단계 펼침 구조로 바뀜. 기본 한 문장 설명은 접힌 안쪽에 있어 기본 노출 요구는 남음 |

남은 검증: 모든 분기의 복사문·복사 실패, 전체 Tab 순서·포커스 표시, 최초 결과 제목 초점, 동작 줄이기 설정, 실물 모바일·화면낭독기·사용자 이해도, 네트워크/저장 여부. 단계 그림의 작은 글자와 현재 상태 표현도 최종 점검이 필요하다. 브라우저의 임시 화면 크기는 원복했다.

R08 비용 상세에는 여전히 ‘처음·이후 청구 카드와 자격별 최대 지원액 상세는 2단계에서 추가됩니다.’가 표시된다. 비용·보호자·제품 전체를 이번 UX 보완으로 완료했다고 볼 수 없다. 이번에는 사이트 코드나 Figma를 수정하지 않았고 테스트/빌드를 실행하지 않았다.

## 6. 다음 작업 제안 — 결과 콘텐츠 이관을 별도 완료 단위로

새 디자인을 다시 요청하기보다 **‘현재 디자인을 유지하면서 15개 결과 콘텐츠와 복사를 원본 수준으로 이관’**하는 작업이 적절하다. 제품 검색·전체 기준·보호자 전체 구현을 동시에 묶을 필요는 없다.

필수 완료 기준:

1. 모든 결과에 기관(`action.institution`) + 확인 행동(`action.instruction`) + 실제 문의 문장(`action.ask`) + 센터에서 도움받을 일(`center`)을 제공한다.
2. 조건부 추가 확인(`secondary`)은 R04·R11·R12 등 해당 결과에만, 온라인 문의(`action.online`)는 R09–R15에 원본 조건대로 제공한다. 불필요한 경고·행정 설명을 새로 추가하지 않는다.
3. 센터 질문 3개와 각 확인 목적, 복사 성공/실패 대응을 15개 전부 연결한다. 대표 R02/R08 전용 렌더링을 나머지 결과에 확장한다.
4. 상단 행동 요약·본문·복사는 같은 결과 데이터에서 만든다. 답변 변경 뒤 이전 상태가 남지 않게 한다.
5. 일반 단계 펼침은 개인별 ‘지금 할 일’과 상담 질문을 대신하지 않는다. R15 금액 노출을 포함해 자격별 노출 조건을 복원한다.
6. Handoff §11과 15개 경로를 하나씩 대조하고, ‘문의 문장 있음 / 조건부 안내 맞음 / 질문 3개 / 복사 일치 / 미확인 금액 비노출’ 결과표를 제출한다. 이 범위는 더 이상 ‘2단계 예정’으로 남기지 않는다.

최소 콘텐츠 배열은 다음이면 충분하다. 각 소제목마다 별도 버튼을 추가하거나, 확인 방법을 또 접어 숨기지 않는다.

```text
지금 할 일
먼저 확인할 곳 + 무엇을 확인할지

이렇게 물어보세요
그대로 읽거나 보여줄 수 있는 문의 문장

[해당할 때만] 온라인 문의 연결 / 추가 확인 방법

센터 상담에서 도움받을 일
지금 상담할 수 있는 범위와 실제 구입 전에 확인할 것
```
