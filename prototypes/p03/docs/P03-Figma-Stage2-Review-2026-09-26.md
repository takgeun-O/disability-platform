# P03 Figma Make 2단계 게시본 검토

확인일: 2026-09-26. 대상: [Figma 게시본](https://ochre-bead-10600476.figma.site/validation/hearing-aid-health-insurance).

기준: [P03-Figma-Handoff.md](./P03-Figma-Handoff.md), [직전 콘텐츠 대조 기록](./P03-Figma-Content-Parity-Review-2026-09-26.md), 로컬 `question-note.ts`, `benefit-content.ts`, `bilateral-content.ts`, `BilateralGuide.tsx` 등 기존 구현. 이번에는 원본 Vercel 화면 전체를 다시 순회하지 않고, 현재 게시본을 로컬 전달 명세와 비교했다. Make의 최신 소스는 제공받지 않았으므로 내부 구현 방식·공통 컴포넌트 사용 여부는 단정하지 않는다.

## 결론

**15개 결과의 핵심 안내와 질문 이관은 확인했다. 다만 2단계 전체 완료 판정은 보완 후로 미룬다.** 이전의 ‘어디에서 확인하세요’만 남던 결과가 실제 문의 문장·센터 상담 안내·질문 3개로 채워졌다. 금액 숫자도 대조한 한쪽·양쪽 예시에서 일치했다. 남은 문제는 새 화면을 늘리는 일이 아니라, 이미 합의한 비용 구조·조건·상태 관리·이동 동작을 복원하는 일이다.

아래 항목은 실제 게시 화면에서 재현한 내용이다. 지원 기준 자체를 새로 조사하거나 법적 판단을 변경하는 검토가 아니다.

## 1. 수정 필요: 제품 재검색 후 이전 선택과 복사문이 남음

- 기준: Handoff §7. 입력 변경·재검색 시 이전 선택을 확인 완료처럼 남기지 않는다.
- 재현: R08 → 제품 등록 확인 → `D22018010015` 검색 → `Starkey Picasso 1000 CIC` 선택 → `포낙`으로 입력 변경 후 검색 → 다시 `없는모델검증용999` 검색.
- 실제: 포낙 검색 결과 19개 또는 결과 없음 메시지 아래에 이전 Starkey 선택 카드가 계속 남는다. 결과로 복귀하면 첫 질문과 **실제 클립보드에도 이전 Starkey 모델이 남는다**.
- 영향: 새 모델을 확인하려는 사용자가 이전 제품을 기준으로 상담 질문을 가져갈 수 있다.
- 요청: 검색 입력 변경/재검색 때 선택 상태를 명시적으로 초기화하고, 새 제품 선택 전에는 R08의 일반 질문을 사용한다. 화면·복사문을 같은 유효 선택 상태에서 생성한다. 단순히 전체 기준·보호자 안내를 왕복하는 경우의 선택 보존은 유지한다.
- 추가: 제품 화면에 내부 결과 ID `내 결과(R08)`가 노출된다. 사용자에게는 ‘내 상담 질문’ 등으로 표현한다. 출처명·시행일·확인일은 있지만 제품 화면에서 원문으로 가는 링크는 보이지 않았다.

**완료 보고의 복사 관련 모호한 설명은 구분할 필요가 있다.** 새 제품을 정상 선택한 직후 화면과 복사문에 모델이 반영되는 것은 확인했다. 문제는 복사 버튼 자체가 항상 옛 텍스트를 쓰는 것이 아니라, 재검색 뒤에도 선택이 유효하게 남는 동작이다.

## 2. 수정 필요: 비용 카드가 합의한 구조·도움말·선택적 노출을 보존하지 않음

기준: Handoff §6.2 및 B 계약.

### 결과 화면

- R08·R09·R10의 처음/이후/전체 자격별 금액 카드가 기본으로 모두 펼쳐져 있다.
- 원래의 `지원 금액과 지급 조건 자세히 보기` 접힘 영역이 없다. 현재 세 접힘 항목은 구입 후 절차, 실제 지급액 차이, 직접 청구 서류다.
- 처음/이후 카드 자체에는 비용 구성·청구 시점이 함께 붙어 있지 않다. 구성은 카드 위 긴 요약, 시점은 별도 절차 펼침에 흩어진다.

### 전체 기준 화면

- 구성·시점·지원액은 같은 카드에 있으나, 1280px에서도 위아래 단순 배열이다. 합의한 ‘왼쪽 계산 기준·구성·시점 / 오른쪽 자격별 최대 지원액’ 구조가 아니다.
- 결과 화면과 전체 기준의 카드 문구·구성도 다르다. 내부 코드 중복 여부는 확인하지 않았지만 화면 일관성이 부족하다.

### 두 화면 공통

- `지원금 계산 기준`, `관리비 계산 기준`, `자격별 최대 지원액` 제목이 빠졌다.
- 각 기준액 바로 아래에 두기로 한 ‘이 금액이 그대로 지급되는 것은 아니에요. 자격별 최대 지원액을 확인하세요.’가 카드마다 유지되지 않는다. 결과에는 위쪽 한 번만 있으며 전체 기준 카드에는 없다.
- `차상위 본인부담경감 대상자` 옆 도움말 버튼과 설명이 없다. 따라서 도움말의 Enter/Space·열림 상태·금액 아래 펼침도 검증할 기능 자체가 없다.
- 전체 기준의 실제 지급액 상세에서 후기 관리의 실제 비용·조건 설명, 날짜가 지났다고 자동 입금되는 것이 아니라는 설명, 위임 청구 시 판매업소가 지급받을 수 있다는 설명 등이 축약됐다. 결과 상세에서도 자동 지급·수령 계좌 관련 설명은 확인하지 못했다.

### 단계 펼침의 금액 표현

R08 ‘이후 관리’를 열면 `후기 적합관리비(연 5만 원)를 청구할 수 있어요`라고 나온다. 같은 결과의 비용 카드에는 일반 대상 연 최대 4만 5천 원이 표시된다. 연 5만 원이 계산 기준임을 이 문장에서는 구별하지 않는다. 단계 안내에는 관리 후 별도 청구한다는 절차만 두고 금액은 공통 비용 카드로 모으거나, 기준액·자격별 최대 지원액 구분을 함께 제공한다. 보험 미확인·의료급여에서 이 숫자를 숨기도록 수정한 동작은 유지한다.

요청: 새 금액이나 자격 질문을 추가하지 말고 기존 공통 비용 콘텐츠/도움말 명세를 복원한다. 결과는 요약만 기본 노출하고 상세 카드는 기본 접힘, 전체 기준은 카드 기본 노출을 유지한다. 금액 자체는 현재 대조한 값에서 원본과 일치한다.

## 3. 수정 필요: 보호자 안내의 일부 지급 전제·공식 연결 누락

기준: Handoff §6.3·§12, `BilateralGuide.tsx`, `bilateral-content.ts`.

유지된 내용: 19세 미만과 추가 검사 조건 모두, 나이만으로 확정되지 않음, 공통 안내, 양쪽 최대 예시, 아동이라는 이유만으로 100%가 아님, 분할 지급 시점, 계산식, 확인일 2026-09-25, 기관별 질문 3개.

누락/변경:

1. 금액 앞의 ‘두 보청기 각각에 최대 지급 기준이 적용되고 후기 관리 조건까지 충족했을 때의 합계’가 빠졌다.
2. 실제 지급액은 **각 제품의 고시금액·구입금액과 관리 조건**에 따라 달라지고 **100%도 인정 금액 기준**이라는 구체적 설명이 빠졌다. 현재는 ‘자격과 제품·관리 조건에 따라 달라져요’ 정도로 축약된다.
3. 공식 근거 상세에 계산식과 조항 번호는 있으나, 원문으로 이동할 수 있는 시행규칙·고시 링크가 없다. 전체 기준에는 일부 링크가 있지만 보호자 화면에서 직접 확인할 수 없다.
4. 공식 자료에 직접 명시된 지급기준금액·양쪽 예외·관리 조건 설명이 조항 번호 나열로 축약됐다. 두 기기의 조건을 충족한다는 전제와 실제 계산값의 구분을 상세 안에서 복원한다.
5. 별도 아동 사업의 복지로 URL이 전달한 원문과 다르다.
   - 게시본: `https://www.bokjiro.go.kr/ssis-tbu/twGEWelService.do?welServId=WLF_MTC001&welClsfNo=05`
   - 원본: `https://www.bokjiro.go.kr/ssis-tbu/twataa/wlfareInfo/moveTWAT52011M.do?wlfareInfoId=WLF00001130`
   - 새 URL이 동일 사업으로 정상 연결되는지는 이번에 확인하지 않았다. 확인 근거 없이 바꾸지 말고 기존 검증 링크를 복원하거나 동일 사업 연결을 검증한다.

긴 행정 설명을 기본 화면에 늘리라는 의미가 아니다. 기본으로 필요한 지급 전제만 짧게 복원하고, 공식 기준 설명·계산식·원문은 기존 선택형 상세 안에 둔다.

## 4. 수정 필요: 보호자 직접 진입과 질문 제목 초점

### 직접 링크

`/validation/hearing-aid-health-insurance#one-or-two`로 이동한 뒤 새로고침하면 보호자 안내가 아닌 시작 요약이 나온다. 같은 페이지에서 해시만 바꾸어도 현재 결과가 유지될 뿐 보호자 안내로 전환되지 않는다. URL의 해시와 내부 view 상태를 연결해야 한다.

요약/결과의 버튼으로 보호자 안내에 들어가는 것은 정상이다. 결과 없이 버튼으로 들어가면 상·하단 모두 ‘30초 요약’ 복귀가 표시된다. 이 정상 동작과 직접 링크 실패를 구분한다. 나머지 모든 직접 앵커를 전수 검증한 것은 아니다.

### 질문 바로가기

`병원·센터 질문 보기 ↓`는 해당 위치로 스크롤되지만, 클릭 및 Enter 뒤 질문 제목으로 초점이 이동하지 않는다. 실제 `document.activeElement`는 BODY이고 질문 h3에는 id/tabindex가 없다. 현재 링크는 `#bilateral-questions`를 가리킨다.

요청: 질문 제목에 고유 id와 `tabIndex=-1`을 주고 기존 빠른 이동의 초점 처리 패턴을 사용한다. 이동 뒤 제목의 위치와 다음 Tab 순서를 함께 확인한다. 일반 결과의 ‘지금 할 일 보기’는 Enter 후 `h3#today-tasks` 초점과 이동 완료 후 화면 안의 제목 위치를 확인했다.

## 5. 수정 필요: 미확인 결과에서도 구입·착용 칸을 현재처럼 강조

- 재현: R15(등록 완료 → 보험 모름 → 처방전 있음 → 이력 모름).
- 실제: 상단 ‘전체 절차와 현재 위치’에서 구입·착용 칸이 연노랑(`rgb(255,251,235)`)이며 그 안에 ‘보험 자격 확인 필요’가 들어간다.
- 기대: Handoff의 미확인 처리 원칙대로 특정 한 단계를 현재 위치로 확정하지 않고, 확인 필요 상태를 단계 표시와 구분한다.
- 현재 상태 제목과 본문·복사는 미확인을 올바르게 유지한다. 문제는 지도에서 주는 시각적 의미다. 이전 검토에서 지적한 항목으로 여전히 남아 있다.
- R05·R09·R10·R11–R15의 표시 규칙을 함께 점검하되, 이번 색상 재현 증거는 R15다. 단계를 펼쳐 읽는 행동과 답변 기반 위치를 분리하는 기존 원칙은 유지한다.

## 6. 추가로 정리할 작은 항목

- ‘센터 상담에서 도움받을 일’ 내용은 복원됐지만 소제목 없이 문의 문장 다음 문단으로 붙어 있다. **공식기관에서 확인할 일과 센터에서 상담할 일을 구분하는 짧은 라벨**을 복원하면 좋다. 별도 버튼은 필요 없다.
- 본문 5단계의 핵심 한 문장 설명도 접힌 내부에 있다. 단계·기관명만으로 부족한 사용자에게 기본 설명 한 줄을 보이고 추가 내용만 접는 이전 합의를 재확인한다.
- 기준액 텍스트는 전체 기준에서 11px로 측정됐다. 금액 강조를 낮추는 목적과 별개로 너무 작은 회색 본문은 읽기 어렵다. 계산 기준은 일반 본문 수준으로 두고 실제 최대 금액의 제목·굵기로 위계를 만든다.

문장 사이 공백은 보험 모름+처방 있음/없음/모름 화면과 복사에서 정상이다. 이전 지원 있음과 모름의 질문이 구분되고, 기존 기기를 보유했다고 단정하지 않는다. 결과 상단의 다음 행동은 기관뿐 아니라 실제 행동 문장까지 복원됐다.

### 상호작용·화면

- 마지막 질문과 선택지를 유지하며 결과가 아래에서 갱신됨. 앞선 보험 답변 변경 시 이후 답과 결과가 초기화됨.
- R05·R15의 이후 관리 펼침에서 이전 문제인 연 5만 원 문구가 미노출됨. R11–R15 기본 결과에 개인용 지원율·지급액 카드가 없음.
- R08 선택 제품이 화면 질문 및 실제 클립보드에 반영됨. R10으로 답을 바꾸면 미확인 질문/복사로 갱신됨.
- R08 제품 선택 후 전체 기준 하단 복귀 및 보호자 상단 복귀에서 답변·결과·모델 질문이 보존됨.
- R03 심사 대기의 보호자 하단 복귀, R15 미확인 결과의 보호자/전체 기준 왕복에서 결과와 답변 보존 확인. 상·하단 모든 조합을 모든 결과에서 전수 검사한 것은 아님.
- 보호자 질문 3개가 기관명과 함께 복사됨. 보호자와 일반 결과의 복사 버튼 모두 14px 글자·44px 높이로 측정됨.
- Enter/Space로 결과 복사, 보호자 복사, 단계 펼침, 복귀 및 빠른 이동을 표본 확인. 보호자 질문 제목 초점은 위 결함 있음. 전체 Tab 순서는 미검증.
- 실제 제품코드 검색, 포낙 별칭 19개 결과, 6개에서 ‘더 보기’ 후 12개 표시, 결과 없음 안내 확인. 206개 전체 데이터 동일성·정확 일치 우선순위·모든 검색 정규화는 미검증.
- 1280px 및 390px·320px의 브라우저 화면 크기를 적용해 검사. 결과/비용/전체 기준/보호자의 확인한 상태에서 가로 넘침 없음(390px: 문서 폭 384px, 320px: 314px; 스크롤바 폭 제외). 버튼 44px 유지. 기기 에뮬레이션 중 화면 캡처 축척 한계가 있어 전 영역 시각 검증 완료로 보지 않음. 임시 화면 크기는 원복함.
