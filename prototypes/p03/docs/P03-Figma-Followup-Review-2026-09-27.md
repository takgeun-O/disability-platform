## 2. 남은 주요 문제: 비용 안내가 일부 화면에만 반영됨

### 결과와 전체 기준이 다름

결과에는 ‘지원금 계산 기준 / 관리비 계산 기준 / 전체 지원금 계산 기준’이 추가됐다. 그러나 전체 기준에는 여전히 ‘처음 청구 · 기준액 111만 원 …’ 등의 이전 카드가 남아 있고 도움말도 없다. 금액은 같지만 문구·구조·도움말이 일치하지 않는다. 내부 공통 컴포넌트 사용 여부는 소스 미확인으로 단정하지 않는다.

요청: 한 공통 비용 카드와 콘텐츠를 결과·전체 기준에서 사용하고, 결과는 기본 접힘 / 전체 기준은 기본 노출이라는 차이만 유지한다.

### 도움말이 자격명 옆이 아님

결과에는 ‘차상위 본인부담경감 대상자란?’라는 독립 details가 전체 합계 카드 아래에 하나 생겼다. Space로 열리고 본문은 올바르게 나타난다. native details 자체가 열림 상태를 제공하므로 수동 aria 속성이 없다는 이유만으로 접근성 실패라고 판단하지 않는다.

다만 요구한 ‘자격명 옆 설명 버튼 → 그 자격의 금액 아래 설명’ 구조는 아니다. 전체 기준과 보호자에는 해당 도움말 진입점이 없다. 자격명을 읽는 곳에서 설명을 발견할 수 있도록 공통 도움말을 적용해야 한다.

### 배치·위계도 일부 미반영

- 1280px에서 결과와 전체 기준 모두 단순 위아래 배열. 계산 기준·구성·시점과 자격별 최대 지원액의 좌우 구분이 없음.
- ‘자격별 최대 지원액’ 제목이 없음.
- 각 기준액 아래에 두기로 한 ‘이 금액이 그대로 지급되는 것은 아니에요…’가 카드별로 없음. 결과 상세 위에 한 번만 있음.
- 계산 기준 글자 크기가 여전히 11px. 본문 수준 가독성으로 복원 필요.
- 날짜가 지나면 자동 입금되는 방식이 아니라는 안내, 개인별 청구 가능일·수령 계좌 및 위임 청구 시 판매업소 수령 가능성은 결과의 지급 조건 상세에서 여전히 빠져 있음.

## 3. 작은 잔여 항목

- 제품 화면에는 고시명·시행일·확인일은 있으나 공식 원문 링크가 여전히 보이지 않음.
- 본문 단계별 핵심 설명은 아직 펼친 내부에 있음. 기존 요청의 ‘기본 설명 한 줄 + 선택형 상세’는 미반영.
- R15 지도에서 황색은 없어졌지만 ‘보험 자격 확인 필요’는 여전히 구입·착용 칸 안에 있음. 시각적 오인은 줄었지만 ‘특정 단계와 별도 확인 필요 상태 구분’은 일부만 반영. 결과 제목·사실·질문은 미확인을 유지함.

## 4. 검증 범위와 한계

- R08·R09·R10·R15 및 보호자 직접 진입, 제품 선택/검색/왕복을 직접 조작했다.
- 1280px 비용 DOM 배치 확인. 390px·320px에서 확인한 전체 기준과 펼친 결과 비용/도움말에 가로 넘침 없음. 320px 보호자 질문 이동과 가로 넘침 없음 확인. 임시 화면 크기는 원복했다.
- 새 모델을 다시 선택하는 모든 경우, 날짜 경계의 최신성 전환, 모든 직접 앵커, 전체 Tab 순서, 복사 실패, 실물 모바일, 화면낭독기, 사용자 이해도는 이번에 전수 검증하지 않았다.
- Make 코드의 타입 검사·lint·빌드는 직접 실행하지 않았다. 해당 성공 문구는 Make의 보고다.
- 애플리케이션·Make 코드·게시 상태를 변경하지 않았다. 이번에는 이 기록만 추가했다.

## 5. 사용자가 문구를 직접 수정하는 방법

파일 다운로드·재업로드 없이 Figma Make 안의 Code 편집기로 기존 파일을 수정할 수 있다. 이 프로젝트 보고 기준 P03 파일은 `src/pages/HearingAidGuide.tsx`다. 로컬 Next.js 파일과 Make 파일은 별도이며 자동 동기화된다고 가정하지 않는다.

권장 순서: 원본 Make 프로젝트 → Code → 파일 선택 → Cmd+F로 문구 검색 → 작은 범위의 문구 수정 → Preview 확인 → 필요할 때 Publish 창의 Update.

일반 문자열의 글자만 바꾸는 수정과 JSX의 줄바꿈은 구분한다. JSX 문단의 강제 줄바꿈은 `<br />`, 문자열 데이터의 `\n`은 렌더링 방식에 따라 줄바꿈이 보이지 않을 수 있다. 상담 질문은 화면뿐 아니라 복사 결과도 확인한다. 반응형 줄바꿈을 맞추려고 공백을 여러 개 넣지 않는다.

공식 자료:

- [코드 직접 편집](https://help.figma.com/hc/en-us/articles/33649966245783-Edit-the-code-of-a-functional-prototype-or-web-app): Code 탭과 파일 탐색기. 문서상 직접 편집은 유료 플랜 Full seat 대상. Cmd+S는 코드 포맷 기능으로 설명되어 있으므로 이를 게시 버튼으로 안내하지 않는다.
- [AI 크레딧 절약](https://help.figma.com/hc/en-us/articles/40097793879191-Best-practices-for-optimizing-AI-credits-in-Figma-Make): 작은 변경에 직접 코드 편집과 Cmd+F 활용 권장.
- [Make 편집 도구](https://help.figma.com/hc/en-us/articles/42009840449175-Edit-a-Figma-Make-file): 새 속성 패널의 Apply는 AI 크레딧을 사용. 기존 파일과 새 파일의 편집 UI 차이가 있으므로 모든 화면 클릭 편집을 무료라고 안내하지 않음.
- [게시 업데이트](https://help.figma.com/hc/en-us/articles/31304586129559-Publish-update-or-unpublish-a-Figma-Make-file): 편집만으로 공개 URL이 바뀌지 않으며 Publish 창에서 Update 필요.

편집 링크에서 이번 세션은 로그인되지 않은 보기 상태였다. 사용자의 로그인된 계정에서 Code 버튼 위치·편집 권한을 직접 확인한 것은 아니며 위 안내는 공식 문서와 프로젝트 파일 보고에 근거한다.
