# P03 Figma Make 통합 요청 프롬프트

작성: 2026-09-26. 사용할 프로젝트: [Desktop Homepage Wireframe](https://www.figma.com/make/3BOg49ITxCde7KQ0lakmXx/Desktop-Homepage-Wireframe?p=f&t=UyuOEh9CXKaci7Cz-0).

**현재 실행할 요청:** 1단계 게시본 UX 검토 후 사용자 동의가 완료되었다. 지금은 [P03-Figma-UX-Refinement-Prompt.md](./P03-Figma-UX-Refinement-Prompt.md)의 보완 요청과 갱신된 Handoff를 전달한다. 아래 최초 1단계 요청을 다시 실행하지 않는다. 보완본 검토 후 아래 2단계를 진행하되, Handoff §4.2의 질문 유지·본문 단계별 펼침 합의를 계속 보존한다.

실행 방법:

1. 기존 Make 프로젝트에서 `P03-Figma-Handoff.md`를 첨부하고 아래 **1단계 요청** 블록만 붙여 넣는다. 새 Make 프로젝트를 만들지 않는다.
2. 1단계 결과의 디자인·동선을 검토한다. 필요하면 그 단계의 게시 URL을 Codex에 전달해 중간 검토한다. 대표 화면 구현을 전체 통합 완료로 취급하지 않는다.
3. 2단계를 진행할 때 `src/app/validation/hearing-aid-health-insurance/data/hearing-aid-products.json`을 추가 첨부하고 **2단계 요청** 블록을 붙여 넣는다. 첫 단계 첨부 문서가 대화에서 더 이상 읽히지 않으면 같은 문서를 다시 첨부한다.
4. Make 수정본 게시 URL과 완료 범위를 Codex에 전달한다. 이 문서와 Handoff의 R01~R15/V01~V12를 기준으로 비교 검토한다. 실제 서비스 코드 통합은 디자인 방향을 정리한 뒤 별도 작업으로 진행한다.

로컬 절대경로는 Make가 읽을 수 있는 첨부가 아니다. 파일을 실제로 첨부해야 한다. 전체 저장소나 별도 캡처 묶음은 필요 없다.

## 2단계 요청 — 1단계 검토 후 붙여 넣기

```text
1단계에서 정리한 공통 디자인과 진입 동선을 유지하면서 P03 통합의 2단계를 진행해 주세요. 같은 프로젝트에서 작업합니다. 첨부 P03-Figma-Handoff.md와 hearing-aid-products.json을 기준으로 아직 연결하지 않은 내용을 완성해 주세요.

게시본 UX 보완에서 합의한 Handoff §4.2도 유지합니다. 결과를 만든 질문/선택지 유지, 같은 자리 결과 갱신, 조건부 범위 문구의 위치, 지금 할 일 강조, 상태의 의미를 보존한 공통 강조색, 본문 단계별 펼침, 화면 폭에 따른 콘텐츠 일치를 되돌리지 마세요. 펼친 안내는 개인의 현재 위치를 변경하지 않습니다.

1. 질문·결과 전체
- Handoff §10의 Q1~Q4 원문과 조기 종료를 구현하고 §11의 R01~R15를 모두 연결합니다. 결과 수가 15개여도 일부 제목이 같을 수 있습니다. 답변 사실·미확인 항목·상담 질문이 다른 경로를 합치지 마세요.
- 보험 자격 모름은 필요한 처방·지원 이력 질문을 계속 묻되 미확인으로 유지합니다. 해당 결과에는 건강보험 금액·지원율·비용 상세를 개인 지원액처럼 표시하지 마세요.
- ‘받은 적 있어요’와 ‘기억나지 않아요’를 구분합니다. 모름은 지원 기록의 존재부터 확인하고, 과거 지원이 있어도 현재 기기 보유를 단정하지 마세요.
- 답변을 바꾸면 이후 답변과 결과·질문·복사문을 함께 갱신합니다. 문장 연결의 공백·줄바꿈을 유지합니다.

2. 전체 기준·비용·보호자 안내
- 전체 기준은 등록 / 대상 / 양쪽 지원 / 금액 / 5단계 / 상담 준비 / 출처의 7개 섹션입니다.
- 기존 화면 안의 비용·서류·검사·근거 펼침을 불필요하게 별도 페이지로 만들지 마세요.
- 건강보험+처방 완료의 처음/이전 있음/이력 모름 결과(R08~R10)에만 후속 건강보험 상세를 표시하며 상담 질문 3개 뒤, 기본 접힘을 유지합니다.
- 처음 청구·이후 청구 카드 안에서 계산 기준·구성·청구 시점과 자격별 최대 지원액을 구분합니다. 전체 합계에도 같은 원칙을 적용합니다. 수치·최대·실제 지급 조건·출처·확인일을 Handoff §6/§12 그대로 보존합니다.
- ‘차상위 본인부담경감 대상자 설명’ 버튼은 자격명 옆, 본문은 해당 자격의 금액 아래에 인라인으로 펼칩니다. 의료급여와 혼동하지 않게 합니다.
- 보호자 안내는 같은 #one-or-two 한 곳으로 연결합니다. 제목 바로 아래와 하단 복귀, 대상 요약 다음 ‘지금 확인할 일’/‘병원·센터 질문 보기 ↓’, 선택형 검사 조건, 양쪽 금액 예시, 선택형 근거·계산, 기관별 질문·복사, 별도 사업 링크 순서를 유지합니다.
- 나이만으로 양쪽 지원을 확정하지 않습니다. 두 기기의 최대 지급·관리 조건을 충족한 계산 예시이며 공식 문서에 합계가 직접 적혀 있다는 뜻이 아니라는 구분을 유지합니다. 아동이라는 이유로 100% 지원이라고 표시하지 마세요.

3. 복귀·복사·접근성·제품
- 전체 기준·보호자·제품 조회 왕복 후 답변·현재 단계·선택 제품을 유지하고 결과 제목에 초점을 복귀합니다. 실제 결과가 없으면 요약으로 복귀합니다. 내부 왕복과 재시작/새로고침 초기화를 구분합니다.
```
