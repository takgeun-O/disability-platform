# 댓글 수정 초안 복구 (2026-11-05)

## 적용 범위
게시글 상세의 Comments 편집 흐름만 변경한다. 마이페이지 InlineComments는 현재 조회·좋아요·등록만 제공하므로 새 수정 기능을 추가하지 않았다. 공유 CommentItem, contentUpdatedAt 표시와 검증, 서버 API는 유지한다.

## 상태와 사용자 동작
- 일반 요청 실패: 현재 편집창과 입력을 유지한다. 자동 저장/재전송하지 않는다.
- COMMENT_NOT_FOUND / POST_NOT_FOUND: 현재 수정 불가로 보관한다. 숨김인지 삭제인지는 단정하지 않는다.
- 일반 404/네트워크 오류: 숨김으로 간주하지 않는다.
- 유효한 공개 GET에서 본인 댓글을 확인: 명시적인 '수정 이어가기'를 제공한다. 렌더 후 입력란에 포커스하고 이동한다. reduced-motion을 따른다.
- 현재 조회 범위 밖 또는 조회 실패: 초안 유지, 상태 재확인·보기·복사·삭제를 제공한다. 전체 페이지를 자동 탐색하지 않는다.
- 다른 작성자로 확인: 이어가기 차단. 서버의 최종 권한 검증은 그대로 적용된다.
- 최신 본문이 편집 시작 본문과 다름: 최신 서버 본문과 보관 초안을 비교 표시하고 사용자가 눌러야 재개한다. updatedAt 차이만으로 충돌을 판단하지 않는다.
- 최신 본문과 입력이 같음: 추가 저장이 필요 없다고 안내한다. 특정 요청이 성공했다고 단정하지 않는다.
- 삭제는 확인 후 수행한다. 보기 영역을 접는 것은 삭제가 아니다. 복사 실패 시 직접 선택을 제공한다.

## 수명과 요청 보호
편집 상태에 회원 ID, 게시글 ID, 댓글 ID, 원본 본문, 입력, contentUpdatedAt 및 마지막 확인 댓글을 보관한다. 화면 메모리만 사용하며 이탈/새로고침 이후 복구를 보장하지 않는다. 인증 확인 중·로그아웃 실패에는 유지하고 확정 비로그인·새 로그인 시작·다른 회원으로 변경되면 제거한다. 새 댓글 작성 초안은 기존 별도 흐름을 유지한다.

GET 적용은 기존 요청 번호·인증·화면 수명 검사를 통과한 fetched만 사용한다. 입력 갱신은 함수형 state update로 지연 GET 중 입력을 보존한다. PUT의 CSRF 이후 검사 및 화면 반영에는 인증과 화면 소유권을 함께 적용한다. 동일 세션의 늦은 쓰기 결과에 대한 기존 데이터 무효화는 유지한다.

## API 한계
공개 목록에서 본인 댓글 확인은 현재 읽기 가능성의 근거이며 이후 수정 성공 보장이 아니다. 특정 댓글 조회/위치 API가 없어 목록 밖 대상은 확정 판정하지 않는다. PUT은 content만 전송하고 조건부 버전 검사가 없으므로 동시 수정 덮어쓰기를 완전히 방지할 수 없다. 숨김 본문을 가져오기 위한 관리자 API 호출은 없다.

## 검증 안내
community-comments-browser.mjs에 PC/320px의 복구·본문 비교·명시적 재개, 목록 밖/조회 실패/작성자 불일치, 삭제 취소, 복사 실패 대체, 불확실 PUT 후 동일 서버 본문, 지연 GET 중 새 입력 보존 검사를 추가했다. 기존 취소 무시 응답/인증 경합/커서 범위 검사는 유지한다. 실제 실행 결과는 별도 검토 ZIP의 최종 로그와 README를 기준으로 한다.
