# 목록 좋아요 표시와 댓글 링크 후속 변경

기존 feat/community-post-like 미커밋 구현을 보존한 UI 후속 작업. 백엔드/API/회원 데이터 변경 없음.

## 동작
- PostListReactions를 공개 피드·마이페이지 내 게시글에서 공유. 좋아요는 공유 메모리 상태를 구독하는 읽기 전용 숫자이며 변경 요청을 보내지 않는다.
- 댓글은 실제 AppLink. 기존 from 및 목록 저장 콜백을 유지하고 #comments-title로 이동한다. 새 탭과 무JS에서도 기본 링크로 동작한다.
- PostDetail은 명시적인 댓글 해시로 진입할 때만 댓글 제목으로 초점을 옮기고 smooth 스크롤한다. 모션 감소 환경은 즉시 이동. 일반 제목 링크와 댓글 CRUD/좋아요 갱신은 이 효과를 다시 실행하지 않는다. 예약 프레임은 unmount 시 취소한다.
- 상세의 좋아요 등록·취소와 기존 인증/CSRF 처리는 유지. 선택 하트는 빨간색(#c43f50). 목록에서도 본인이 좋아요한 하트만 같은 색상으로 표시한다.

## 실제 실행
- Node 24로 lint, typecheck, unit test 348/348 통과.
- 별도 /private/tmp 복사본에서 production build 통과. 기존 8443 개발 서버 보존.
- post-reactions-navigation-browser.mjs: 프로덕션 8464 + 제어된 모의 API 8858, 7/7 통과.
- 1440/390/320 각각 공개 피드·내 게시글: 좋아요 버튼 부재, 댓글 링크 키보드 실행·목적지·댓글 제목 초점, 가로 넘침 없음, 상세 좋아요 등록 빨간색 및 목록 복귀 후 숫자 갱신.
- 무JS: 목록 숫자 표시와 실제 댓글 해시 링크 이동.
- 캡처와 results.json은 같은 이름의 폴더에 보관. 최초 lint/typecheck는 기본 Node23으로도 통과했으나 지원 버전 Node24로 다시 실행했다.

## 검증 범위
실제 Spring 변경 요청과 실물 Safari는 이번에 실행하지 않았다. 목록에서 좋아요를 직접 클릭하던 이전 post-likes-browser.mjs는 이전 UX 기록으로 남아 있으며 이번 결과로 재실행 통과를 주장하지 않는다. 새 요구사항의 목록 동작은 새 회귀 파일로 검증했다. 상세의 모든 오류/경합 시나리오는 이번 UI 후속에서 반복하지 않았다. 이번에는 검토 ZIP 요청이 없어 새 ZIP은 생성하지 않았다.
