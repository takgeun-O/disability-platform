# 대시보드 신고 상세 모달 — 2026-11-17

## 사용자 동선

- 대시보드의 개별 상세 링크를 일반 클릭/키보드로 실행하면 같은 대시보드를 배경으로 중앙 모달을 연다. 주소는 `/admin/reports/{reportId}`다.
- 직접 진입, 새 탭, 새로고침은 기존 신고 전용 페이지다. 대시보드 전체 접수 목록 링크와 신고 관리 메뉴의 목록·분할 상세는 유지한다.
- 모달 처리 성공 후 자동 이동하지 않는다. 결과와 포커스를 모달에 유지하고 대시보드를 새 GET으로 갱신한다. 행이 없어져도 모달은 열린다. 정상 닫기 후 원래 링크, 제거된 행은 처리 대기 제목으로 포커스를 복귀한다.

## 라우팅·복귀

`AdminDashboardRouteHost`가 인증 경계 안에서 대시보드와 이번 문서에서 연 모달을 호스팅한다. native history에 신고 ID와 닫기 방식, 문서 수명 토큰만 저장한다. Next의 공식 native-history 어댑터가 내부 라우터 필드를 보존하고 NavigationGuard가 이력 번호를 관리한다. Next의 `__NA` 등을 직접 복사하면 이 버전의 경로 동기화가 생략되므로 전달하지 않는다.

대시보드에서 열면 push 1회, 닫기는 그 직전 대시보드로 back 1회다. 문서 토큰은 새로고침 시 달라지므로 예전 이력 메타데이터가 있어도 전용 페이지를 표시한다. 활성 모달은 현재 pathname과 신고 ID가 일치해야 한다. 다른 관리 화면에 남지 않는다.

콘텐츠 관리 복귀 주소는 정확한 `/admin/reports/{양의 안전정수}?from=dashboard`만 추가 허용한다. `AdminReportReturnLink`의 일반 탐색만 새 대시보드와 같은 신고 모달을 연다. 새 탭/직접 진입/새로고침은 전용 페이지로 간다. 관리 화면에서 복귀한 모달의 명시적 닫기는 `/admin`으로 replace하여 다시 관리 화면으로 돌아가지 않는다. 이 경우 브라우저 뒤로가기는 실제 이전 방문인 관리 화면으로 이동한다. 기존 전용 페이지 출발과 목록·선택 복귀 주소는 변경하지 않는다.

## 공유 상세와 보호

AdminReportDetail의 presentation을 panel/page/modal로 구분하며 상세·처리 로직은 하나다. 모달은 고정 헤더와 한 본문 스크롤을 사용한다. 상단 이동·오류·처리 결과 포커스는 해당 스크롤 안에서 작동한다. 모바일은 visualViewport 높이/위치를 사용한다.

성공 알림은 모달 안에서 표시한다. 대시보드 갱신 실패는 처리 실패와 분리하며 이전 수치·기준 시각과 재시도 안내를 유지한다. POST는 자동 반복하지 않는다. 성공 직전의 오래된 대시보드 GET은 취소하고 새 요청을 보낸다. 계정 요청 범위와 언마운트 취소로 늦은 결과를 차단한다. 상세/대시보드 401·403은 모달과 배경 데이터를 모두 제거한다.

OverlayDialog 공통 변경은 중첩 창의 문서 스크롤 잠금 공유, 최상위 창의 키보드 처리, 배경의 inert/aria-hidden 및 원래 속성 복구다. 확인창 취소는 상세 모달로 포커스를 돌려주며 잠금은 최종 창이 닫힐 때만 해제한다. 기존 NavigationGuard와 API·DB·신고 정책은 변경하지 않았다.

## 2026-11-17 후속 검토 반영

- 공유 상세의 선택적 `onServerStatus` 콜백은 현재 세션/요청 유효성 확인을 통과한 상세 GET과 확정 POST 결과만 전달한다. 기존 목록/전용 페이지는 콜백을 지정하지 않는다.
- 대시보드 모달은 종결 상태를 처음 확인하면 서버 집계를 GET으로 갱신한다. 모달 열기 수명에 속한 ref를 요청 전에 표시하여 POST와 후속 GET, 반복 상세 조회, 리렌더의 중복 자동 갱신을 막는다. 자동 갱신 실패는 기존 값/시각을 유지하고 수동 재시도로 복구한다.
- `notify`는 내 POST 성공 토스트만 표시한다. 충돌/불확실 요청의 상세 종결 확인은 토스트를 호출하지 않으며 기존 안내를 유지한다. 카운트 직접 변경, POST 재전송, 폴링은 없다.
- 추가 조치 없는 종결은 “현재 콘텐츠 상태를 변경하지 않고”로 설명한다. 숨김·처리 완료는 정상/이미 숨김을 구분하며, 최신 확인이 필요한 때는 상태를 확정하는 설명 대신 확인 안내를 사용한다. 저장된 handlingOutcome 표시는 유지한다.
- 데스크톱 모달은 fit-content 높이와 기존 최대 높이를 사용한다. auto는 inset 배치에서 늘어나는 것이 브라우저 검사로 확인되어 사용하지 않았다. 모바일 화면 채움과 본문 한 곳의 스크롤은 유지한다.
