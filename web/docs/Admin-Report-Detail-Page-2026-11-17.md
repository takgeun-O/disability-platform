- 대시보드 개별 신고 → `/admin/reports/{reportId}`. 대상 콘텐츠 ID를 사용하지 않는다.
- 대시보드 접수 신고 보기 → 기존 전체 기간/전체 대상/사유 없음/RECEIVED/OLDEST/page=0 목록.

- 사이드바 신고 관리 → 기존 목록·선택 상세 분할 화면. 전용 경로에서도 해당 메뉴가 활성화된다.
- 직접 진입·새로고침은 상세 GET만 사용한다. 잘못된 ID는 API 호출 전에 거부한다.

`AdminReports` 안의 상세 구현을 `components/admin/AdminReportDetail.tsx`로 이동하여 두 화면이 조회·처리·재조회·입력 보호·성공 포커스를 공유한다. 목록 갱신 콜백이 전달된 경우에만 목록을 재조회한다. 반환 주소는 각 화면이 명시적으로 전달한다. 전용 화면은 64rem 최대 너비와 페이지 스크롤을 사용하며 기존 선택 패널의 내부 스크롤은 유지한다.

게시글·댓글 관리의 복귀 경로 검증은 정확한 `/admin/reports/양의안전정수`만 추가 허용한다. 쿼리·fragment·외부 주소·정수 범위 초과는 허용하지 않는다. 기존 목록 조건 복귀는 유지한다. 콘텐츠 관리 후 복귀하면 다시 상세 GET을 실행한다.

처리 성공 후 같은 상세 화면에 머물며 결과 제목으로 포커스를 옮긴다. 확정된 처리 결과와 재조회 실패를 구분하고 복구는 GET만 수행한다. handlingOutcome과 현재 콘텐츠 상태를 서로 추정하지 않는다. 백엔드·API·DB·보안 정책은 변경하지 않았다.

## 검증 한계와 수동 확인

실제 관리자 세션으로 상세 조회·처리한 검증은 미실행이다. 프로덕션 스모크의 실제 API 검증은 공개 게시글 조회와 초기 HTML에 한정된다. 실제 DB·기존 회원·신고를 임의 변경하지 않았다. Safari와 문서 간 이동의 네이티브 beforeunload 확인은 수동 검증 대상으로 남긴다. 기존 공통 NavigationGuard는 변경하지 않았다.

로컬 전용 테스트 데이터와 관리자 세션으로 대시보드 → 개별 상세 → 세 처리 방식 각각의 결과 확인 → 대시보드 복귀 및 집계 확인을 수행한다. 게시글·댓글 관리에서 테스트 콘텐츠를 복원한 뒤 해당 신고로 돌아와 현재 상태만 바뀌고 저장된 처리 결과는 유지되는지 확인한다. 실제 운영 데이터에는 실행하지 않는다.
