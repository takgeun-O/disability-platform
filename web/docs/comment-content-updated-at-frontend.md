# 댓글 본문 수정 시각 프론트 연동 (2026-11-05)

기준: c73c589194d7cde5c69fbd9bd7638c15a8c7520a, feat/admin-operation-log.
작업 시작 Git 상태는 깨끗했다. 기존 운영 기록·댓글 복원·인증 토스트 구현은 기준 커밋에 포함되어 있으며 이번 작업에서 재작성하지 않았다.

## 계약과 표시

| 경로 | 응답 검증 | 표시 |
|---|---|---|
| 공개 댓글 / 내 게시글 인라인 | 필수 contentUpdatedAt: 유효한 ISO 시각 또는 null | null이면 수정됨 없음, 시각이면 수정됨 |
| 내 댓글 VISIBLE | 동일 | 작성 시각 옆에 수정됨 |
| 내 댓글 HIDDEN / PARENT_HIDDEN | contentUpdatedAt도 반드시 null | 본문 수정 시각·수정됨 비노출 |
| 관리자 댓글 모든 상태 | 필수 nullable 시각 | 본문 수정 / 최종 변경을 구분, null은 기록 없음 |

누락·undefined·숫자·빈 문자열·불가능한 날짜는 거절한다. 기존 writtenInstant를 재사용하여 임의 보정을 하지 않는다. updatedAt으로 대체하지 않는다. 기존 null 데이터에 과거 수정이 없었다고 단정하지 않는다.

일반 댓글의 작성 시간은 기존 WrittenTime(createdAt)이다. 기존 수정 시각 툴팁은 없어 새로 추가하지 않았다. 관리자는 한국 시각 초 단위 표기를 재사용한다. 게시글 날짜 표시와 운영 기록 처리 시각은 변경하지 않았다.

POST는 commentId, PUT은 204이므로 시각을 클라이언트에서 만들지 않는다. 기존 서버 재조회 결과를 그대로 사용한다. 전체 댓글 객체를 저장하는 상태/캐시 경로는 새 필드를 유지하며 커서·정렬·좋아요 저장소·요청 소유권은 변경하지 않았다. 등록 성공 기록(ID와 제출 본문만 포함)에는 가짜 시각을 추가하지 않았다.

## 검증 범위

content-updated-at.test.mjs: 세 API의 required/nullable 계약, 잘못된 날짜, 숨김 비공개, 원문 소수점 정밀도, 204 수정 후 GET 값 사용.
community-comments-browser.mjs: entity 변경만으로 수정됨 미표시, 숨김/복원 모의 상태 후 표시 보존, 실제 본문 수정→GET→표시, 동일 본문의 저장 비활성 및 표시 유지, 1440/320px.
inline-comments-browser.mjs, member-comments-browser.mjs: 각 화면에서 nullable/시각의 서로 다른 표시.
admin-detail-browser.mjs: 본문 수정과 최종 변경의 서로 다른 실제 시각, 기록 없음.
기존 테스트의 댓글 DTO fixture에 필수 필드를 추가했다. 테스트 전용 변환에서도 값을 전달하고 숨김 때 null로 가린다.

동일 본문 PUT의 백엔드 정책은 API 문서로 확인했다. UI는 기존부터 동일 본문의 저장 버튼을 비활성화한다. 브라우저에서 비활성 버튼을 제출시키지 않았으며, PUT 204/GET 보존 계약은 단위 모의 테스트로 별도 검증한다.

실제 Spring/DB 통합 테스트는 이번 작업에서 실행하지 않았다. 운영 계정/콘텐츠/DB 변경 없음. API의 본문 수정 기록 정책 자체는 백엔드의 책임이다.

수동 확인: 미기록 댓글을 관리자 숨김→복원 후 공개 댓글 새로고침하여 수정됨이 없는지 확인한다. 실제 본문을 수정한 댓글은 수정됨이 보이고, 이후 운영 조치에도 관리자 본문 수정 일시는 유지되는지 확인한다. 마이페이지 숨김 댓글에는 본문과 수정 시각이 없어야 한다.
