# 신고 숨김·처리 완료 프론트 연동 (2026-11-16)

기준: feat/content-report, fb164465019eb452c9bf0d8487a085ce4613e226. 작업 시작 시 미커밋 변경 없음.
이 기록은 2026-11-13 문서의 당시 미구현 제한을 대체하는 후속 구현 기록이다. 이전 검증 수는 이번 결과에 합산하지 않는다.

## 구현

- RECEIVED 상세에 숨김·처리 완료 / 추가 조치 없이 처리 완료 / 신고 기각을 구분한다.
- `/api/v1/admin/reports/{reportId}/hide-and-resolve`에 정규화된 handlingReason만 전송한다. 콘텐츠 숨김 API와 resolve를 순차 호출하지 않는다.
- 기존 최신 세션 CSRF, 사유 1~500 Unicode 코드 포인트 검증, 중복 제출 방지, 이동 보호, 늦은 응답 차단을 재사용한다.
- 대상 없음·삭제는 숨김 동작만 제한한다. 이미 숨겨진 대상은 기존 숨김 유지 안내와 함께 처리할 수 있다. 댓글 부모 상태는 추측하지 않고 서버 오류로 안내한다.
- 입력 폼에 신고 번호, 게시글/댓글 ID, 선택 동작, 처리 의미와 사유를 표시한다. 별도 확인 모달은 추가하지 않는다.
- 상세 handlingOutcome은 필수 nullable이고 과거 LEGACY_UNKNOWN을 허용한다. 신규 처리 응답은 non-null이며 LEGACY_UNKNOWN을 거부한다. 누락·잘못된 값·동작과 맞지 않는 성공 응답은 성공으로 표시하지 않는다.
- 처리 결과는 저장된 값이다. 현재 콘텐츠가 복원되어도 CONTENT_HIDDEN 이력을 유지한다. null은 아직 처리되지 않음, LEGACY_UNKNOWN은 과거 조치 여부 확인 불가로 표시한다.
- 실제 반환 outcome으로 성공 안내를 결정한다. 성공 후 목록·건수·상세·현재 콘텐츠를 조회하고 범위 밖 페이지를 보정한다. 필터에서 빠진 선택 상세는 유지하며 안내한다.
- POST 성공과 후속 GET 실패를 구분한다. 일부 조회 실패 시 복구 상태를 유지하고 재조회는 GET만 수행한다. 응답 유실은 최초 POST 성공으로 단정하지 않으며 사유를 보존한다.
- REPORT_ALREADY_HANDLED는 이번 성공이 아닌 충돌로 안내한다. POST/COMMENT_NOT_FOUND 및 POST/COMMENT_DELETED는 구분하고 최신 정보를 조회한다. 재조회 결과 대상 없음·삭제가 확인되면 열린 숨김 폼의 실행도 제한한다.
- 백엔드·DB·API 계약·CSS·공통 레이아웃 변경 없음.

## 검증 한계와 로컬 수동 확인

실제 인증된 관리자 hide-and-resolve POST 및 DB 트랜잭션은 이번 프론트 작업에서 실행하지 않았다. 실제 연동 smoke는 공개 GET만 검증했다. 백엔드 회귀 테스트도 이번 범위에서는 재실행하지 않았다. 추가 백엔드 수정 필요 사항은 발견하지 못했다.

전용 로컬 테스트 데이터로 다음을 직접 확인할 수 있다.
1. 다른 테스트 회원의 게시글/댓글 신고를 접수하고 관리자에서 신고 번호와 대상 ID를 확인한다.
2. 숨김·처리 완료를 실행해 네트워크에 해당 신고 ID POST 한 번과 handlingReason만 전송되는지 확인한다.
3. RESOLVED / CONTENT_HIDDEN과 현재 숨김 상태를 확인한다. 같은 대상의 다른 신고는 그대로 남아야 한다.
4. 이미 개별 숨겨진 테스트 대상 신고에서는 CONTENT_ALREADY_HIDDEN을 확인한다.
5. 테스트 콘텐츠를 별도로 복원한 뒤 이력 CONTENT_HIDDEN이 유지되는지 확인한다.
6. 추가 조치 없는 완료·기각에서는 NO_CONTENT_ACTION이며 공개 상태가 바뀌지 않는지 확인한다.

기존 운영 회원·콘텐츠에는 이 검증을 실행하지 않는다.
