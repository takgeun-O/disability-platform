# 댓글 수정 실패 UI 단순화 (2026-11-05)

이 기록은 기존 `comment-edit-draft-recovery.md`와 `comment-draft-dialog-followup.md`의 복구 UI 정책을 대체한다. contentUpdatedAt 계약과 인증·조회 소유권은 유지한다.

- PUT의 HTTP 404 + `COMMENT_NOT_FOUND` / `POST_NOT_FOUND`: 해당 편집을 종료하고 입력을 정리한다. 목록을 재조회하고 “현재 이 댓글을 수정할 수 없어요.” 알림을 표시한다. 조회 중 비활성화되는 새로고침 버튼 대신 댓글 제목에 포커스를 둔다.
- 근거: `CommentUpdateService`는 공개 가능한 부모/댓글 조회 실패 시 이 코드를 사용한다. `GlobalExceptionHandler.handleCommentUpdate`가 404로 변환한다. 숨김·삭제를 구분할 수 없어 특정 사유는 말하지 않는다.
- 작성자 불일치는 `ACCESS_DENIED`로 변환되므로 일반 403과 구별할 수 없다. 인증·CSRF·권한 오류의 기존 처리를 유지하며 임의로 초안을 폐기하지 않는다.
- 네트워크·타임아웃·5xx·일반 404 등 결과 불확실: 기존 편집폼과 원문 입력 유지, 폼 내부 안내. 자동 PUT 재전송 없음.
- 목록에서 빠진 편집 대상: 삭제로 판정하지 않고 댓글 영역에 편집폼을 유지한다. 서버 목록/커서에 가짜 항목을 추가하지 않는다. 다시 조회되면 해당 댓글 위치에 편집폼을 표시한다. 명확한 업무 오류를 받으면 종료한다.
- 유효한 실제 조회의 본문이 현재 입력과 같으면 `original` 및 `contentUpdatedAt`을 갱신한다. 함수형 상태 갱신으로 GET 대기 중의 최신 입력을 비교하고 보존한다. 다르면 기준과 입력을 그대로 두고 짧은 안내를 표시한다.
- 복구 배너, 확인·비교·복사 모달과 전용 스타일은 제거한다. 일반 수정 취소/다른 댓글 편집 전환/페이지 이탈 확인은 유지한다.
- 새 댓글 입력은 별도 상태이며 특정 수정 실패로 정리하지 않는다. 기존 인증 수명에 따라 확정 로그아웃·계정 변경 시 편집 입력을 정리한다.
- 서버의 조건부 쓰기 API가 없어 동시 편집 충돌을 완전히 막지는 못한다. 실제 서버 콘텐츠를 변경하는 검증은 수행하지 않는다. 실행 결과와 화면은 검토 ZIP의 README 및 로그를 참조한다.
