## 직접 조작한 기존 화면

- PC 1440px: 홈 메뉴 → IYUM 소개 앵커 → 이용 가이드 → 질문 시작.
- 건강보험 대표 경로: 등록 완료 → 건강보험 → 처방전 받음 → 처음 신청 → ‘구입 전 제품·비용 상담’.
- 결과 → 전체 기준 보기 → 이전 결과 복귀. 질문 복사 성공, 복사문에 선택한 상황 포함.
- 정보 찾기 → 복지·지원정보 → 유일한 안내에서 같은 P03로 이동.
- 모바일 390px: 메뉴 열기·정보 하위 메뉴·Escape 후 정보 찾기 버튼 초점 복귀.
- 모바일 의료급여: 등록 완료 → 의료급여 → 처방전 받음 → 지원 이력 기억 안 남 → 이번 신청 안 함 → ‘주민센터 신청 단계’.
- 320px 현재 P03 가로 넘침 없음(문서 폭 320px).
- 제품 검색 ‘Picasso’: 현행 목록에서 13개 결과. 제품 목록 확인 후 7일 경과 경고 확인. 외부 공식 판매처 서비스에 실제 검색/예약을 요청하지 않음.
- `#one-or-two`, `#center-product-check` 직접 진입 시 해당 안내 표시.

이 검토는 실제 현재 프론트엔드 화면 조작이다. 질문과 제품 검색은 로컬 데이터/상태이며 실제 정책 API 검증이 아니다. 신규 계정·게시글·정책 데이터를 만들지 않았다.

## 문제와 개선 이유

1. **‘이용 가이드’의 이름과 내용이 다름:** 사이트 이용법처럼 보이지만 보청기 제도 안내 한 건이다. 복지 목록과 중복 진입이므로 상위 분류에서 제외하고 목록/홈 바로가기를 유지한다.
2. **소개가 홈 앵커로만 연결됨:** 서비스 목적·로고 의미·현재 제공 범위를 충분히 설명하기 어렵다. `/about`을 제안하고 홈 요약 및 기존 앵커는 유지한다.
3. **목록/P03와 현재 브랜드의 시각적 차이:** 회색·검정, 2px 모서리, 작은 일부 보조 문구가 남아 있다. 현재 네이비·청록 토큰, 읽기 쉬운 크기와 테두리를 적용하는 시안을 만들었다.
4. **모바일 도입이 길다:** 기존 시작 화면은 요약·면책 안내 뒤에 시작 버튼이 있다. 시안은 질문을 먼저, 긴 설명은 하단/펼침으로 배치한다. 검토 바를 포함한 첫 질문 카드 상단은 390px에서 약 457px, 320px에서 약 482px다.
5. **목록 한 건에 과한 필터는 실익 없음:** 현재는 필터 없이, 확장 시에는 제도/공고 구분 및 적용 전후 조건을 명확히 표시한다.
6. **제도와 공고가 섞일 위험:** 보청기 제도 안내에는 마감일·D-day를 넣지 않는다. 실제 공고 연계는 아직 없다.
7. **준비 중 기능과 실제 기능의 혼동 여지:** 기기·기관은 준비 중, 검색과 홈 최근 글은 예시, 커뮤니티 목록/상세/작성은 실제 구현으로 구분한다. 홈 ‘센터 방문 전 질문’ 별도 카드가 준비 중이지만 P03 결과 안의 상담 질문은 이미 제공한다. 별도 카드의 장래 연결 목적은 후속 정리 항목이다.
