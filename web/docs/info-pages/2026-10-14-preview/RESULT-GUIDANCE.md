# P03 결과 안내 · 기관과 행동 중심의 4차 시안

2026-10-14. 현재 전체 방향/소개에 대한 사용자 의견을 보존하고 **설문 결과 안내 시안만** 수정했다. 서비스 코드 반영은 아직 하지 않았다.

## 무엇이 바뀌었나

이전에는 모든 결과에서 보청기센터의 질문 3개를 같은 비중으로 노출했다. 등록 전의 주민센터 방문이나 처방 전의 병원 진료가 우선이어도 센터 질문이 이어져 다음 행동이 불분명해졌다.

현재 결과는 아래 네 항목을 세로 순서로 안내한다. PC에서도 2×2로 흩어놓지 않는다.

1. **먼저 확인할 곳:** 실제 결과의 담당 기관 + 건물/병원/판매점 선형 아이콘. 청록 강조.
2. **이곳에서 무엇을 물어볼까요?:** 해당 기관에 물을 기존 `contactQuestion`을 읽기 쉽게 표시. 파랑 강조. 현재 상황과 이 질문을 복사한다.
3. **할 일과 준비할 것:** 기존 `nextAction`, `nextActionNote`, `secondary`와 원본 설명에서 정리한 준비 메모. 황갈색 강조.
4. **이번 단계 다음에는:** 현재 단계 확인/완료 후 이어질 흐름. 청회색 강조. 조건이 불명확하면 확인부터 하도록 하며 승인·자격·첫 신청을 추정하지 않는다.

색만으로 구분하지 않고 01~04 번호·제목·아이콘을 함께 사용한다. 아이콘은 장식용 aria-hidden이며 기관명은 텍스트로 제공한다. 기존 결과 제목·질문 유지·부드러운 이동·현재 위치 색상·절차 토글은 유지한다.

## 등록 신청 전 화면의 실제 안내

- 먼저 확인할 곳: **주소지 주민센터**
- 질문: “청각장애 등록을 처음 알아보고 있어요. 어떤 병원에서 검사받고, 검사 후에는 어디에 자료를 내면 되나요?”
- 할 일: “방문해서 청각장애 등록 신청 방법과 진단받을 병원을 안내받으세요.”
- 준비: “이미 진단 자료가 있다면, 등록 신청에 제출할 수 있는 자료인지 확인하세요.”
- 다음: “안내받은 이비인후과에서 검사·진단” → 검사·진단 자료를 받은 뒤 주민센터에 제출 → 심사와 등록 결과 확인.

필요 서류 목록이나 검사 횟수·지원 자격을 새로 만들지 않았다. 준비할 자료가 원본에 특정되어 있지 않으면 해당 기관에서 안내받도록 한다.

## 현재 기관 질문과 센터 상담 질문의 구분

- 모든 결과의 주 질문은 해당 결과의 **실제 담당 기관에 묻는 기존 질문**이다.
- 제품·비용에 관한 추가 센터 질문은 **R08(건강보험 센터 상담), R18(의료급여 결정 후 센터 상담)**에서만 접힌 상세로 제공한다. 획일적인 ‘센터에서 물어볼 질문 3개’ 제목은 제거했다.
- ‘이 질문 복사하기’는 현재 상황 + 담당 기관 + 현재 기관 문의만 복사한다. 다른 단계의 센터 질문이 섞이지 않는다.
- 센터 단계에서 펼친 ‘추가 상담 질문 복사하기’는 기존 `buildCopyText` 스냅샷 전체 문구를 그대로 복사한다. 두 버튼 모두 실패 시 선택 가능한 텍스트와 초점을 제공한다.
- 초기 단계에서도 제품 상담을 받을 수 있다는 기존 정책을 금지로 바꾼 것이 아니다. 지금 필요한 기관 문의를 앞세우도록 정보 우선순위를 조정했다.

## 2026-10-14 · 5차: 미선택 시작·확인 체크·전체 기준 연결

- 기존 결과 주소 자동 답변 채움 제거. 신규 진입/새로고침은 미선택이며, 예시 불러오기 선택에서만 답변을 채운다. 전체 기준에서 복귀할 때는 답변·체크·스크롤·클릭한 링크의 초점을 유지한다.
- R01~R04, R06~R21에 문의 후 확인할 내용과 할 일 체크 항목 추가. 원본의 기관·문의 문장·nextAction·조건은 유지했다. `p03-action-guidance.js`의 checklist는 화면 표시/개인 메모용이며 원본 결과 결정 로직과 분리했다.
- 체크는 결과 코드가 같아도 답변이 바뀌면 초기화한다. 새 진입·새로고침에도 초기화하며 상세 왕복에는 유지한다. 선택만으로 자격·신청·완료를 단정하거나 자동으로 다음 단계로 넘기지 않는다. 저장·전송하지 않는다.
- `actionCopy()`는 01~04 순서와 `[ ]`/`[x]` 줄바꿈 양식을 만든다. 현재 상황·기관·질문·확인 항목·준비 항목·조건·다음 단계가 포함된다. 기존 센터 추가 질문 복사도 별도로 보존한다.
- 공단 onlineLink 분기에는 원본 공단 글 문의 주소를 표시한다. 의료급여에는 기존 전체 기준에서 제공하던 129 채팅상담 안내를 연결하되 일반 제도 상담과 개별 신청 상태 확인을 구분한다. 병원/센터 온라인 창구를 임의로 만들지 않았다.
- `p03-reference-snapshot.js`: 현재 :8443 전체 기준에서 등록·대상·금액·절차·제품 확인·센터 상담·출처를 읽어 보관했다. 양쪽 금액/조건 및 보호자 질문 복사 원문도 별도 보관했다. 정책 사실은 변경하지 않고 인라인 디자인만 제거했다. 참고 원본 SHA-256을 파일에 기록했다.

## 2026-10-14 · 6차: 일괄 노출된 상세 링크 제거

사용자 검토에 따라 모든 결과의 준비 카드 ‘관련 절차·준비사항 자세히 보기’와 다음 단계 카드의 ‘다음 절차 자세히 보기’를 제거했다. 내용보다 링크가 반복되고, 다음 단계와 맞지 않는 일반 설명으로 연결될 수 있던 문제다. 사용하지 않는 `checklist.detail` 속성도 삭제했다.

R08의 실제 청구 설명을 보완하는 ‘판매업소 위임·직접 청구 방법 보기’는 유지했다. 기존 온라인 문의, 전체 기준·양쪽 지원 진입, 명확한 금액·제품 설명 연결, 공식 출처도 유지한다. 첫 미선택·체크·복사·답변/상세 복귀와 현재 정책 문구는 변경하지 않았다.

`checks/revision-6-browser.mjs`의 19개 + 기본 회귀10개 = **이번 수정 후 29개 통과**. 28개 완료 조합에서 준비 카드 상세 링크가 0개, 다음 단계 상세 링크는 R08에만 1개인지 확인했다. 링크를 없앤 자리에 검사 항목도 없애는 대신, 체크/초점 복귀는 실제 남은 전체 기준 링크로 계속 검증했다. 1440/390/320 캡처는 `captures/revision-6/`이며, 5차 기록과 소스는 `history/revision-5/`에 보존했다.

main과 HEAD를 유지하고 서비스 코드는 수정하지 않았다. 전체 서비스 테스트/빌드·실제 상담 접수·정책 최신성 검증은 이번 범위에서 실행하지 않았다. 최신 파일을 외부 검토용 ZIP에 현재 상태 그대로 담으며 커밋·push·배포하지 않는다.
