## 확정된 정보 구조

상단은 PC·모바일 공통으로 **IYUM 소개 → 커뮤니티 → 정보 찾기**다.

| 항목 | 실제 반영 시 경로 | 역할 |
|---|---|---|
| 로고 | `/` | 홈 복귀 유지 |
| IYUM 소개 | `/about` (신규 제안) | 목적·도움·로고 의미·제공/준비 구분 |
| 커뮤니티 | `/community` | 현재 기능 유지 |
| 정보 찾기 → 복지·지원정보 | `/welfare` | 제도 안내와 미래 모집 공고의 목록 |
| 정보 찾기 → 기기 정보 | `/devices` | 준비 중 상태 정확히 표시 |

| 목록/홈 주요 안내 → 보청기 | `/validation/hearing-aid-health-insurance` | 기존 경로와 해시·쿼리 보존 |

인증 영역은 그대로 유지한다. 푸터에는 제공되는 소개·지원·커뮤니티 링크만 배치한다. 이용 도움말/문의는 내용과 기능이 생기면 푸터에서 제공하는 방향이며 빈 링크를 만들지 않는다.

## 목록의 두 상태

- **현재 1건:** 제도 안내만 한 건. 검색/유형/지역 필터와 페이지네이션을 넣지 않는다. 작은 ‘내 상황 확인하기’ 강조와 실제 안내 카드, 공고 준비 중 안내를 제공한다. 대상의 확정 판정이나 지역을 새로 만들지 않는다.
- **확장 예시:** 기존 제도 안내 1건 + 실제 사업이 아닌 가상 공고 A/B/C. 모든 예시에 가상 표기. 임박 공고 A, 상시 B, 마감 C로 상태별 배치를 검토한다. 날짜와 D-day는 2026-10-14 기준 고정 예시다.
- 필터 선택은 아직 미적용이며 ‘적용된 조건’과 구분한다. 적용하면 목록 제목에 초점, 0건이면 조건 변경/초기화 안내. 초기화는 선택/적용 상태와 검색어를 함께 비우고 전체로 즉시 돌아간다.
- 모바일 필터는 기본 접힘이다. 제도 안내에는 접수 상태/기한을 붙이지 않고, 지역 값이 없는 안내를 전국 지원으로 추정하지 않는다.
- 공고 수집, 정렬 API, 마감 자동 판단, 신청 기능은 구현하지 않는다. 운영기관·공식 출처·정보 확인일이 실제 데이터에 생기면 공고 상세와 메타데이터로 표시한다.

## P03 시안의 범위

질문과 결과는 현재 `HearingAidGuide.tsx`의 선택지/계산 함수를 읽어 만든 **39개 중간 상태·28개 완료 조합 스냅샷**이다. `preview/p03-snapshot.js`에 원본 경로와 SHA256을 기록했다. 새 정책이나 자격 판정을 만든 것이 아니다.

시연 가능: 질문 선택, 의료급여 Q4/Q5와 모름, 이전 질문, 결과, 질문 복사 및 직접 복사 대체 안내, 상세 발췌 보기/복귀, 답변 초기화. 상태는 메모리뿐이며 네트워크나 브라우저 저장소로 보내지 않는다. 화면 선택기의 ‘대표 결과’는 검토를 위한 건강보험/처음 신청 예시이며 실제 이용자의 자격 판정이 아니다.

배치 제안: 짧은 제목 → 현재 질문. 결과에서는 답변 요약 접기 → 전체 절차/내 위치 → 지금 할 일 → 센터 질문 → 세부 설명. 모바일의 전체 절차는 접을 수 있다. 금액은 건강보험 상세 허용 결과 R08/R09/R10에서만 보이며 R09/R10의 이전 이력 확인 문구도 유지했다. 의료급여/보험 모름 결과에 건강보험 금액을 표시하지 않는다. 기존 일반 요약의 숫자를 초기 질문에서 앞세우지 않고 조건에 맞는 상세로 옮기는 배치다.

**전체 기능 복제는 아니다.** 전체 금액·양쪽 지원 표, 제품 선택/판매처 확인, 공식 문서 링크는 기존 서비스의 같은 해시로 새 탭 연결한다. 답변을 새 탭에 전달하지 않는다. 상세 페이지는 시각 구조 확인을 위한 발췌다. 원래 페이지의 모든 세부 펼침 상태·스크롤 복원·제품 선택 연동까지 재구현했다고 보고하지 않는다. 상단 절차 표시는 요약이며 시안에서는 절차별 자세한 내용은 결과 하단에서 펼친다.

## 실제 서비스 반영 시 반드시 재사용/보존

- `GlobalNav`, `Shell`, `HomePage`, `WelfarePage`, P03의 현재 컴포넌트와 기존 토큰을 사용한다. 이 HTML 전체를 Next 코드로 그대로 덮어쓰지 않는다.
- AppLink/NavigationGuard의 이탈 확인, 취소 시 초점·메뉴 유지, 로그인/로그아웃·인증 UI는 변경하지 않는다.
- P03의 computeResult/getResultInfo/computeJourney/computeFacts/buildCopyText와 28개 결과 조합, 의료급여/모름/이력 분기, 금액 노출 조건을 보존한다.
- HearingAidBenefits/RegistryCheck/DirectClaimGuide의 조건·내용·출처·최신성 경고, 복사 실패 대체, 제품 선택 질문, goTo/goBackFromInner 복귀와 초점을 보존한다.
- 기존 URL과 검색 차단을 유지한다. `/about` 제목·현재 메뉴·브레드크럼과 목록 복귀만 추가/정돈한다.
- 승인 후 그 시점의 Git 상태를 확인한다. 이번 자료 때문에 미추적 파일이 생기므로 이를 보존하면서 브랜치를 결정한다. 강제 초기화나 사용자 변경 덮어쓰기 없음.
- 실제 소스 수정 후 단위·타입·lint·빌드와 메뉴/키보드/모바일/P03 분기·복귀·복사 회귀를 실행한다. 기존 커뮤니티 무JS 404는 별도 알려진 이슈이며 이번 시안에서 재검사하거나 신규 실패/해결로 분류하지 않았다.

## 이번 검증의 경계

서비스 파일을 바꾸지 않았으므로 전체 서비스 빌드·인증 API 검사를 불필요하게 재실행하지 않았다. 정적 JS 구문 검사, 시안 브라우저 조작·15개 화면/크기 조합의 넘침 검사, 현재 사이트 직접 탐색, 소스 해시 비교, `git diff --check`를 실행했다. 모의 지원사업·시안 상호작용은 실제 API 검증이 아니다. 새 DB 데이터는 없다. 기존 사이트의 서버는 유지했다.

Safari/Firefox·모바일 실기기·스크린리더·전체 P03 정책/금액 최신성은 이번 단계에서 검증하지 않았다. 시안 확인 후 같은 세션에서 실제 컴포넌트에 반영하는 것이 다음 단계다.

### 최종 시안 검사 결과

브라우저 검사 **10개 통과**. 15개 화면/크기 조합(5화면×1440/390/320), 메뉴 순서/키보드, 현재 1건, 확장 필터/초기화/빈 상태, P03 건강보험·의료급여/모름/복사/왕복, 목록 재진입 초기화, API 호출/저장소/런타임 오류 없음. 선택 상자의 접근 가능한 이름과 초기화 버튼의 form.reset 이름 충돌은 시안에서 수정 후 재검사했다. 소스/테스트 125개 파일 해시가 작업 전과 같고 tracked diff는 없다.

재현 스크립트는 `checks/preview-browser.mjs`(9개), `checks/preview-extra.mjs`(1개)다. localhost:8450 미리보기를 실행한 상태에서 Playwright가 설치된 환경의 `PLAYWRIGHT_MODULE`을 지정해 Node로 실행한다. 예: `PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node checks/preview-browser.mjs`. 프로젝트에 Playwright 의존성을 추가하지 않았다.
