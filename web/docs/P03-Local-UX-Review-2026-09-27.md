## 수정 내용

### 1. 의료급여 처방 확인 단계의 중복 강조

기존에는 `current`와 `check-needed`에 모두 노란색 계열을 적용했다. 의료급여의 처방 미발급·미확인 결과는 병원과 구입 단계가 동시에 강조됐으며, 상단 요약과 본문 단계의 색상 규칙도 달랐다.

- 의료급여 + 처방 미발급: 병원 처방만 현재 단계로 강조.
- 의료급여 + 처방 미확인: 상태는 `check-needed`로 유지하고, 별도의 `highlight`로 병원 처방만 강조. “처방 확인 필요 · 먼저 확인” 표시.
- 구입 단계는 이후 과정으로 표시. 구입 전 주민센터 신청·결정 안내는 기존 단계 상세에 유지.
- 상단과 본문이 같은 색상·굵기 판단을 사용. 다른 미확인 상태는 중립색 유지.
- 미확인 병원 단계를 완료 또는 확정된 현재 단계로 바꾸지 않음.

### 2. 의료급여 구입 전 신청 단계의 담당 기관

- 신청 대기·미신청·신청 여부 모름 결과의 구입 단계에 주민센터·시군구 표시.
- 상세 설명은 “구입 전 신청·결정 확인”, 상태 문구에도 구입 전 신청임을 표시.
- 지원 결정 통보를 받은 결과는 기존 센터 상담·구입 준비와 보청기센터·판매업소 표시 유지.
- 5단계 구조와 결과별 상담 질문은 변경하지 않음.

### 3. 내부 화면 왕복 복원

기존 코드에는 펼친 `details[id]`와 이동 버튼 ID를 저장하는 구조가 있었지만, 실제 펼침 영역에는 ID가 없고 호출부도 버튼 ID를 전달하지 않았다.

- 펼침 영역에 화면별 고정 ID 부여. 결과와 전체 기준의 5단계 ID를 분리.
- 모든 내부 진입 버튼이 자신의 ID를 전달.
- 화면 렌더링 직후 펼침 상태를 복원하고 스크롤과 초점을 복원. 임의의 지연 시간에 의존하던 복원 제거.
- 전체 기준으로 복귀하면 이전 스크롤 위치와 진입 버튼 초점을 복원.
- 설문 결과로 복귀하면 기존 목적대로 결과 제목에 초점·스크롤 이동. 제목에 80px 스크롤 여백 적용.
- 직접 보호자 링크 진입 후 결과가 없으면 요약 제목으로 복귀.
- 답변·선택 제품·검색 결과는 기존 부모 상태로 보존.

## 2026-09-28 · 설문 상단 절차 통합과 결과 읽기 순서

### 변경 범위

사용자가 승인한 흐름: **전체 절차와 내 위치 → 설문 질문 → 현재 상태 → 지금 할 일 → 상담 질문 → 선택형 상세**.

- `src/pages/HearingAidGuide.tsx`: 상단의 읽기 전용 `CompactJourneyBar`를 `GuidedJourney`로 교체. 결과에 반복되던 5단계 목록은 제거. 전체 기준의 기존 `ExpandableJourneySteps`는 유지.
- `src/pages/HearingAidGuide.css`: 위 안내에 한정한 스타일. 데스크톱 5열, 480px 이하 5행. 모바일 버튼 높이 최소 44px. 본문과 상세 설명의 읽기 순서 일치.
- 단계 버튼을 누르면 설명 하나만 표시하고, 다시 누르면 닫힘. 기본 접힘. `aria-expanded`, `aria-controls`, 고유 ID, 이름 있는 설명 영역, 키보드 초점 표시 적용.
- 현재 위치의 노란색은 기존 답변 계산과 색상 규칙으로 결정. 펼친 단계는 중립색 테두리와 화살표로 구분하며 실제 현재 위치를 변경하지 않음. 미확인 상태를 완료나 확정된 현재 위치로 바꾸지 않음.
- 단계 설명과 보험별 담당 기관·안내는 기존 계산 데이터를 그대로 사용. 보험 자격 관련 기본 흐름 주의 문구는 필요한 결과에서 상단 지도 위에 한 번 표시.
- 펼친 단계의 상태는 부모에 보관하여 전체 기준·보호자·제품 화면 왕복 후에도 유지. 답변 변경 시 열린 설명의 내용도 해당 보험·등록 상태에 맞게 갱신. 처음부터 확인하면 접힘.
- 현재 상태 아래에 답변 사실을 짧은 `dl` 요약으로 통합. 보험·처방·지원 이력 미확인 정보와 복사문용 사실 데이터 보존.
- 중복된 다음 행동 배너와 `지금 할 일 보기` 버튼을 제거. 다음 행동을 강조 카드의 첫 문장으로 배치하고, 기관·문의 문장·센터에서 도움받을 일로 연결.
- 첫 결과 출현 시 결과 제목이 약 80px 여백 아래에 오도록 부드럽게 이동하여 바로 아래 지금 할 일이 보이도록 조정. 결과 제목 초점 및 내부 화면 복귀 동작 유지. 이전 결과의 예약된 이동·초점 타이머는 정리.
- 답변/선택 제품에 따라 복사문이 바뀌면 복사 버튼 상태를 초기화해 이전 성공 알림이 남지 않게 보완. 복사문 생성 및 실패 시 수동 복사 대체 처리 코드는 그대로 유지.

위 변경은 이전 기록의 결과 안 절차 표시·`지금 할 일 보기` 버튼에 대한 설명을 대체한다. 지원 조건·금액·질문/결과 분기·출처는 변경하지 않았다.

- 화면별 `idPrefix`로 라디오 그룹 이름·제목·설명·도움말 ID를 구분한다. 라디오에 초점을 유지하고 변경된 제목은 `aria-live`로 전달한다. 기존 내비게이션의 펼침 상태 복원 로직을 재사용한다.
- `src/pages/HearingAidGuide.css`: 공통 안내 스타일, 상세 펼침의 여백/포커스/최소 44px 조작 영역을 적용했다. 비용 카드는 기존 데스크톱 2열, 좁은 화면 1열 배치를 그대로 사용한다.
- 정책 자료를 새로 해석하거나 기준 금액·지원율·조건·출처·확인일을 변경하지 않았다. 기존 양쪽 합산 예시 데이터를 그대로 재사용한다.

### 실제 검증

- 실제 로컬 브라우저에서 건강보험+처방 완료+첫 지원 결과 확인. 상담 질문 3개가 비용보다 먼저 나오며, 한쪽 선택과 기본 접힘 상태가 표시된다. 보기 선택은 접힘 영역 밖에 있다.
- 키보드 방향키로 한쪽→양쪽→한쪽 전환: 선택한 라디오에 초점 유지, 제목/요약/카드 금액 동시 갱신, 양쪽 선택 시 상세 펼침 확인. 전환 전후 답변 요약·지금 할 일·상담 질문 본문이 동일함을 확인했다.
- 전체 기준과 결과의 한쪽/양쪽 카드 본문이 각각 완전히 일치한다. 결과→전체 기준에서 보기 변경→결과 복귀: 선택한 보기와 결과 상세 펼침 유지, 결과 제목 초점 복귀, 답변 유지 확인.
- Enter/Space로 차상위 도움말 열기/닫기, 검사 조건과 공식 근거 열기, 명확한 포커스 테두리 확인. radio의 aria-controls 연결, 제목 live 상태, 중복 DOM ID 없음 확인.
- 1280px 데스크톱 카드 359px+359px의 두 영역 배치 확인. 390px·320px에서 카드가 비용 구성/청구 시점→자격별 지원액 순서로 1열 배치되며 긴 금액/조건 문구도 가로 넘침 없이 표시된다. 390px 보기 선택 라벨 높이 44px, 320px에서는 선택지가 위아래로 배치된다.
- 건강보험의 이전 지원 있음/기억나지 않음 결과에서도 선택한 보기 유지, 이전 이력 확인 주의문 유지. 보험 자격 모름+처방 완료+처음으로 답변 변경 후 비용 컴포넌트 미노출. 의료급여+처방 완료+처음+신청 대기에도 미노출 확인.
- 임시 보존 검사(`/tmp/check-iyum-benefit-preservation.cjs`): 질문/결과/여정/복사/검색 21개 선언, 기존 금액 데이터 18개 항목, 카드/양쪽 대상/검사/출처/질문/복사 7개 선언이 변경 전과 동일함을 확인했다. 비용 상단 요약만 새로 추가한 데이터다.
- 직전 임시 분기 검사(`/tmp/check-iyum-medical-history.cjs`)의 24개 결과 조합 및 복사문 생성 일치 검사 통과.
- `pnpm exec tsc --noEmit`, `pnpm build` 통과. 기존 500KB 초과 번들 경고 유지(JS 약 561.43KB). 프로젝트에 lint/자동 테스트 명령은 없다. 검증 탭 콘솔 오류/경고 없음.

### 남은 검증과 작업 범위

- 실제 모바일 기기·화면낭독기·보호자 이해도 평가는 수행하지 않았다. 제품 선택/검색 전체 회귀 및 실제 클립보드 복사 성공/실패는 이번 작업에서 재검증하지 않았다. 복사문 생성 함수와 질문 데이터 보존을 검사했다.
- 변경 파일: `src/pages/HearingAidBenefits.tsx`, `src/pages/HearingAidGuide.tsx`, `src/pages/HearingAidGuide.css`, 이 기록. 브라우저 뷰포트 복원·임시 검증 탭 정리. 새 의존성·답변 저장/전송·커밋·푸시·배포 없음.

## 2026-09-29 · Next.js App Router 이전 후 회귀 확인

현재 통합 웹을 React/Vite에서 Next.js 16 App Router로 이전했다. 위 기록의 `src/pages/`는 당시 경로이며, 현재 화면 소스는 **`src/features/`**에 있다. 과거 검사 결과는 수정하지 않았다.

P03 질문/결과/여정/복사/검색 21개 선언과 금액 데이터, CSS, 206개 제품 데이터, 직접 청구 안내를 보존했다. 기존 임시 24개 분기 검사를 `tests/p03-regression.test.mjs`에 정착시키고 Q1 조기 분기·금액·내부 복귀 검사와 초기 HTML 검사를 추가했다. lint/타입/5개 테스트/Next 프로덕션 빌드·HTTP 검사 통과. 브라우저에서 답변 변경, 제품 선택, 안내 왕복, 비용 보기, 해시 직접 진입, 키보드 초점, 390px/320px를 확인했다. 복사 성공/실패는 브라우저 writeText를 검증용으로 대체하여 확인했으며 실제 OS 클립보드 검증으로 보고하지 않는다.
