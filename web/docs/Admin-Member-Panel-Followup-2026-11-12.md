# 회원 상세 패널 후속 보완 — 2026-11-12

## 변경 범위

기존 회원 목록 + 우측 상세 구조와 회원 정지·해제 API 연동 위에 적용한 프론트 보완이다. API 경로, CORS, 상태 정책, DB, 목록 열 너비는 변경하지 않는다.

- 조치 성공 메시지와 후속 GET 실패를 분리한다. 목록·상세·이력 재조회가 모두 성공해야 복구 잠금을 해제한다. 일부 실패이면 실패 안내와 잠금을 유지한다.
- 결과가 불확실했던 POST는 GET 성공으로 성공했다고 표현하지 않는다. 현재 상태와 이력 확인을 안내하고, POST를 자동 재전송하지 않는다. 명확한 POST 업무 거부는 GET 성공과 별개이므로 오류를 유지한다.
- 이력에 상세 열기별 객체 식별자를 부여한다. 닫기/재진입 및 A → B → A에서 이전 결과·빈 결과·오류를 새 조회 결과로 사용하지 않는다. 인증 캡처와 요청 세대 검증은 그대로 사용한다.
- 수동 복구는 이력 첫 페이지를 함께 조회한다. 기존 이력 페이지 조회를 무효화하고 페이지 0 전환에 따른 중복 GET을 막는다.
- 이메일 복사는 상세 수명에 속하는 별도 컴포넌트다. 버튼 이름과 표시가 `✓ 복사됨`으로 바뀌고 마지막 성공 후 3초 뒤 복귀한다. 지연 복사 결과, 타이머는 상세 종료·회원 변경·탐색 이후 반영되지 않는다. 실패 시 직접 선택 안내를 제공한다.
- 회원 운영 → 조치 이력 → 가입·변경 정보 순서다. 가입·변경 정보는 기본 접힘이고 native details/summary 키보드 동작을 사용한다.
- 이력은 정지/해제 배지, 시각, 상태 변화, 전체 사유, 관리자 ID를 표시한다. 사유 줄바꿈을 보존하며 별도 스크롤 영역은 만들지 않는다. 시간대는 이력 제목 옆에 한 번 표시한다.

## 재현과 검증 방법

수정 전 production 빌드에서 재조회 성공 후 실패 안내 잔존 및 같은 회원 재진입의 이전 이력 노출을 각각 재현했다. 테스트는 제어 가능한 GET 응답 대기와 실제 UI 상태를 사용한다. 복사 타이머는 Playwright 가상 시계로 검증한다.

`web/tests/admin-member-panel-followup-browser.mjs`가 이번 신규 회귀 테스트다. 기존 회원 관리/조치/후속/표시 회귀 테스트를 함께 실행한다. 결과 숫자 및 최종 실행 로그는 이번 검토 ZIP의 README_REVIEW.md와 logs/를 기준으로 한다. 이전 작업의 통과 수를 이번 결과로 합산하지 않는다.

모든 자동 브라우저 검증은 production Next + Chrome + 모의 API이다. 실제 Spring/DB 조치, 실제 브라우저 클립보드 권한 정책은 검증하지 않았다. 캡처 회원·이메일은 합성 데이터다.

## 실제 서버 수동 확인

로컬 테스트 환경의 조치 가능한 일반 회원과 별도 관리자만 사용한다. 기존 운영 회원을 임의 변경하지 않는다.

1. 관리자 로그인 후 테스트 회원 상세를 열고 현재 상태와 이력 건수를 확인한다.
2. 테스트 사유로 이용 정지를 실행한다. 목록·상세의 정지 상태와 새 정지 이력 1건, 저장된 사유·관리자·시각을 확인한다.
3. 이용 정지 해제를 실행하고 정상 상태 및 해제 이력 1건 추가를 확인한다.
4. 조회 실패를 개발자 도구에서 GET만 차단해 재현한다. 차단 해제 후 재조회 버튼으로 안내가 정리되고 POST가 추가되지 않는지 확인한다.
5. 같은 회원 재진입과 다른 회원 왕복, 이메일 복사 권한 허용/거부, 목록 조건 및 뒤로가기 복원을 확인한다.

회원 상태 변경은 이 문서 작성·자동 검증 과정에서 실제 서버에 실행하지 않았다.
