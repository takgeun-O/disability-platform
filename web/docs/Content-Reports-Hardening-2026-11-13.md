# 신고 프론트 후속 보완 (2026-11-13)

## 이번 적용 범위

앞선 미커밋 신고 프론트를 보존하고 다음을 보완했다.

- 같은 신고/같은 URL로의 이동은 NavigationGuard.request 전에 제외한다. 실제 화면 이동의 요청 무효화는 유지한다.
- 신고 접수 결과 불명 상태는 사유·상세 변경으로 해제하지 않는다. 필드 오류만 입력 수정으로 해제한다. 현재 API에는 내 신고 확인 조회가 없으므로 성공 여부를 추정하지 않는다. 창을 닫고 다시 접수하는 명시적인 재시도에는 중복 응답과 기존 사유 유지 안내를 제공한다.
- 신고 관리 폐기 확인창은 회원 관리 CSS와 독립된 중앙 배치·최대 높이·내부 스크롤 스타일을 사용한다. 기존 OverlayDialog의 배경 잠금과 포커스 복귀를 재사용한다.
- 댓글 관리 링크는 hash 대신 `/admin/comments/{commentId}?from=...`로 이동한다. 기존 `GET /api/v1/admin/comments/{commentId}`와 AdminCommentPreview/AdminModeration을 재사용해 첫 페이지 밖의 댓글도 직접 읽는다. 관리 후 신고 화면 복귀 시 상세를 다시 조회한다.
- 공개 신고는 작성자 행의 더보기 → 신고 → 모달 순서이다. 6개 단일 선택 라디오, 댓글 본문 요약, 3줄 상세 입력, 취소·닫기·신고하기를 제공한다. 본인 수정·삭제는 그대로 유지한다.
- 신고 성공 시 모달을 닫고 공통 토스트로 접수를 안내한다. 실패·중복·결과 불명에는 성공 알림을 표시하지 않는다.
- 기존 resolve 선택은 ‘추가 조치 없이 처리 완료’, dismiss는 ‘신고 기각’으로 의미를 명확히 표시한다.

## 미완료: 숨김 후 처리 완료

이 요청은 백엔드 결합 API, 실제 수행 결과 저장, 신규 Flyway, 동시성/롤백 테스트까지 포함한다. 그러나 자동 승인 검토가 첨부 요청문만으로 해당 영속적 백엔드 변경의 명시적 승인이 충분하지 않다며 파일 편집을 두 번 거부했다. 해당 파일은 변경되지 않았으며 마이그레이션도 생성·적용하지 않았다.

따라서 숨김 후 처리 완료 버튼이나 두 POST를 순차 호출하는 우회는 제공하지 않는다. API·Swagger에 미구현 기능을 구현된 것처럼 기록하지 않는다. 백엔드 직접 편집 승인을 받은 뒤 하나의 REQUIRED 트랜잭션에서 관리자 → 신고 → 부모 게시글 → 댓글 잠금 순서를 대조하고, 실제 숨김/기존 숨김/무조치/기각을 저장하는 구현 및 검증이 남아 있다. 기존 종결 데이터는 실제 조치 정보 없음으로 보존해야 한다.

## 검증 구분

타입 검사·린트·단위 테스트·프로덕션 빌드, 신규/기존 브라우저 검증의 실제 결과와 명령은 검토 ZIP README에 기록한다. 브라우저 신고·조치 테스트는 합성 API이다. 실제 Spring 공개 목록·상세와 SSR 비교 smoke는 읽기 전용으로 실행했다. 관리자 로그인·신고 POST 및 PostgreSQL 트랜잭션 통합 검증으로 해석하지 않는다.

앞선 smoke 실패는 SSR이 fixture 서버를 사용하고 smoke가 실제 API를 사용해 서로 다른 데이터를 비교한 조건이었다. 이번에는 별도 Next 서버와 smoke 모두 같은 로컬 8082를 사용한다. 실제 사용자 콘텐츠를 바꾸는 테스트는 하지 않는다.
