# 댓글 수정 기준 및 복구 대화상자 보완 (2026-11-05)

## 기준 본문
유효한 GET의 fetched에서 대상 댓글을 찾고 그 본문이 **응답 적용 시점의 최신 입력**과 같으면 original 및 contentUpdatedAt을 확인된 값으로 갱신한다. 입력 자체는 변경하지 않는다. 함수형 상태 갱신을 사용하여 요청 시작 후 입력된 내용을 보존한다. 따라서 A→B 저장의 응답 유실 후 B를 조회하면 기준은 B이며 다시 A를 입력하면 dirty 및 저장 가능 조건이 모두 참이다.
본문과 입력이 다르면 기준을 일괄 교체하지 않는다. 편집 시작 본문과 달라진 최신 본문은 비교 후 명시적 재개 시에만 새 기준이 된다. updatedAt 비교를 사용하지 않는다. 같은 본문 확인은 특정 PUT의 성공 증거라고 단정하지 않는다.

## UI
기본 화면은 '저장하지 못한 수정 내용이 있어요.'와 '확인하기'만 제공한다. 상세 내용을 기본 목록에 렌더링하지 않는다. 사용자가 연 CommunityDialog에서 복구 가능/수정 불가/확인 불가/본문 변경/동일 내용 상태를 구분한다.
나중에·닫기·Esc는 내용 유지와 확인하기 포커스 복귀, 이어가기는 대화상자 cleanup 이후 렌더 effect에서 입력 포커스와 reduced-motion을 고려한 스크롤을 수행한다. 입력 내용 버리기는 동일 대화상자 내부 확인 단계로 처리한다. 같은 본문이면 '확인 완료'로 보관 상태를 정리할 수 있다. 자동 조회/PUT 재전송 및 자동 모달은 없다.
편집창 유지 중 불확실한 쓰기 오류는 입력창에 인접한 alert로 짧게 표시한다. 오류는 textarea의 aria-describedby와 연결한다. 공유 대화상자 구현 자체는 변경하지 않았다.

## 보존과 한계
기존 contentUpdatedAt 계약·표시, 커서, 정렬, 좋아요, 등록/수정/삭제, 인증·요청·화면 소유권 검사를 보존한다. 초안은 화면 메모리이며 이탈/새로고침 후 복구 불가. 확정 비로그인/계정 교체 시 제거한다. 마이페이지 인라인 수정 기능은 추가하지 않았다.
COMMENT_NOT_FOUND/POST_NOT_FOUND는 현재 수정 불가로만 해석하고 숨김과 삭제를 추측하지 않는다. 목록 밖/조회 실패는 확인 불가다. 개별 댓글 위치 API나 조건부 PUT이 없으므로 전체 자동 탐색과 완전한 동시 수정 충돌 방지는 제공하지 않는다. 백엔드/DB/API 계약 변경 없음.

실행 결과와 캡처는 이번 검토 ZIP의 README_REVIEW.md와 verification 디렉터리를 참조한다. 이전 검토 로그를 이번 최종 검증으로 재사용하지 않는다.
