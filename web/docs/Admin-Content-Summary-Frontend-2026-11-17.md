# 관리자 콘텐츠 요약 프론트 연동 (2026-11-17)

## 화면과 계약

게시글 목록 `/admin/posts`의 제목·설명 다음, 필터 전에 전체 콘텐츠 요약을 표시한다. 댓글 목록은 게시글 상세 안에 있으므로 별도 라우트나 상세 안의 중복 요약은 만들지 않는다. 전용 게시글·댓글 상세에서 목록으로 돌아오면 목록 진입 조회로 새 요약을 받는다.

`GET /api/v1/admin/content/summary`를 기존 adminGet(세션 쿠키·no-store·공통 오류)으로 호출한다. 필수 필드·null 불허·유효한 날짜/시각·0 이상의 안전한 정수를 런타임 검증한다. 목록 길이나 필터로 수치를 계산하지 않는다. Java long 중 JavaScript 안전 정수 범위 밖의 수치는 기존 adminCount 정책대로 응답 오류로 처리한다.

카드 순서: 오늘 작성 게시글 / 오늘 작성 댓글 / 현재 숨김 게시글 / 현재 숨김 댓글. KST baseDate 문자열을 그대로 표시하고 queriedAt은 writtenTime으로 한국 시간 표시한다. 오늘 작성과 현재 숨김은 다른 조건이며 댓글 자체 상태를 사용한다. 목록과 요약의 동일 DB 스냅샷은 가정하지 않는다.

## 조회·조치·오류

AdminPosts 소유 hook을 URL로 key가 바뀌는 목록/상세 영역 밖에 둔다. 필터·정렬·페이지·상세 선택만으로 요약을 재요청하지 않는다. 첫 진입, 수동 새로고침, 해당 관리 영역의 게시글·댓글 숨김/복원 성공 뒤에 조회한다. 현재 화면에 새 삭제 기능은 추가하지 않았다.

AdminModeration의 확인된 성공 지점에 선택적 onSuccess callback만 추가한다. 기존 목록/상세 refresh, 조치 성공 메시지·포커스·이력 정책은 유지한다. 실패·불확실 응답에서 이 callback을 호출하지 않는다. 요약 실패는 성공한 조치를 재전송하지 않으며 요약 재시도는 GET만 한다.

요약 요청은 이전 controller를 취소하고 현재 요청 소유권과 세션을 함께 확인한다. 전송 취소를 무시하는 응답도 반영하지 않는다. 중복 수동 갱신은 막고 조치 성공은 필요한 최신 조회로 이전 요청을 대체한다. unmount 시 요청을 취소한다. 401은 기존 세션 만료, 403은 이전 목록/상세를 제거하는 권한 오류로 연결한다.

첫 로딩/실패는 0으로 표시하지 않고 미조회 표시를 유지한다. 성공한 0은 0건이다. 재조회 실패는 이전 수치와 이전 조회 시각을 유지하고 오류를 노출한다. 성공 안내는 sr-only status이며 포커스를 이동하지 않는다. 카드 영역은 미조회 때도 유지하여 배치 이동을 줄인다.

## 화면 및 검증 범위

데스크톱 4열, 중간 너비 2열, 좁은 화면 1열이며 모바일에서는 제목과 수치를 나란히 배치해 높이를 줄였다. 스타일은 content-summary 범위에 한정하며 기존 신고/대시보드 카드는 변경하지 않는다.

새 단위 테스트는 응답 계약과 세션 GET을, 새 브라우저 테스트는 카드 매핑/0/로딩/실패/시간대/필터 독립성/조치 후 갱신/GET 재시도/401·403/늦은 응답을 검증한다. 브라우저는 America/Los_Angeles 시간대와 모의 API를 사용해 KST 날짜 유지도 확인한다. 1920·1440·390·320px 캡처를 직접 검토했다.

기존 admin-posts-browser의 /admin→게시글 목록 가정은 현재 대시보드 계약과 달랐다. 초기 진입은 /admin/posts로 수정하고 헤더·모바일 관리자는 대시보드 왕복 후 목록 검색으로 검증한다. 게시글 현재 메뉴의 재조회 방지·페이지 포커스·경계 fallback·오류 재시도 검증을 유지한다. 제품의 대시보드 동작은 바꾸지 않았다.

초기 연동 작업 당시 실제 백엔드 세션 연동은 지정된 계정·세션이 없어 미실행이었다. 모의 API 결과를 실제 Spring 연동으로 보고하지 않는다. 전용 데이터로 게시글/댓글 숨김→요약 GET→복원→요약 GET, 전용 상세에서 목록 복귀를 수동 확인해야 한다. 개발 데이터를 변경하지 않았다. 이번 실행 건수·명령·로그는 검토 ZIP의 README_REVIEW.md와 validation 자료를 참조한다.


## 후속 검증: 작성 시각과 실제 Spring 세션 (2026-11-17)

게시글 목록의 고정 110px 작성 시각 셀에 nowrap이 적용되어 131px 텍스트가 셀을 넘었다. 목록 범위에서 셀을 120px로 확보하고 날짜·시간 사이 줄바꿈을 허용했다. 공통 포맷터·time.dateTime·모바일 카드 구조와 요약 로직은 바꾸지 않았다.

긴 한글/공백 없는 제목으로 1440·1920·390·320px를 확인한다. 브라우저 회귀는 DOM Range의 실제 날짜·시간 경계를 셀 및 overflow 조상과 비교하고, 상태 배지 경계·행 Enter 선택·닫기 후 포커스 복귀도 검증한다. 수정 전 데스크톱 두 사례 실패, 수정 후 네 사례 통과. 문서 전체 scrollWidth만으로 판정하지 않는다.

후속 작업에서는 이전에 허용하여 생성한 전용 관리자 #41, 작성자 #42의 게시글 #105·댓글 #170을 재사용했다. 실제 로컬 Spring 8082와 프론트 8443에서 로그인·요약 GET·UI 숨김/복원을 확인했다. 오늘 작성 게시글/댓글은 2/1로 유지되고 숨김 게시글은 1→2→1, 숨김 댓글은 3→4→3으로 갱신됐다. 각 조치 뒤 요약 GET 1회와 카드 일치, 검색·상태 필터·정렬·페이지 독립성, 전용 상세에서 목록 복귀 시 재조회를 확인했다. 신고 #10·#11의 상태와 handlingOutcome도 불변이었다.

두 콘텐츠는 원래 VISIBLE 상태로 복원했으며 생성된 운영 기록은 보존했다. 새로운 계정·콘텐츠나 DB 변경은 하지 않았다. 실제 오류 주입은 하지 않았으며 401/403·조회 실패·응답 역전은 모의 API 회귀 결과로 구분한다. 검증 시각과 조치별 수치는 후속 ZIP의 final-real-results.json, 읽기 전용 필터/페이지 검증은 final-real-filter-results.json에 기록한다.
