# 신고 요약 후속 보완 (2026-11-17)

## 요약 영역

정상 조회 완료 안내는 `role="status"`를 유지하는 화면 낭독기 전용 요소로 바꾸었다. 일반 흐름에서 높이와 여백을 차지하지 않는다. 로딩·갱신은 가시적인 상태 안내이고 오류는 가시적인 alert로 유지한다. 안내 때문에 포커스를 옮기지 않는다.

기준 안내·집계 날짜·한국 시간 조회 시각을 넓은 화면에서는 같은 행에, 모바일에서는 읽기 편하게 여러 줄로 표시한다. baseDate 문자열과 queriedAt 한국 시간 변환은 그대로다. 신고 요약에 한정해 카드 여백과 숫자 위아래 간격을 줄였으며 숫자 크기·제목·보조 설명·약한 강조를 유지했다. 대시보드 공통 CSS와 데이터 조회 로직은 변경하지 않았다.

동일 합성 데이터/Chrome/화면 크기로 비교한 정상 화면:

| 너비 | 요약 높이 전 → 후 | 목록 시작 Y 전 → 후 |
| --- | --- | --- |
| 1920/1440 | 276.6 → 182.6px | 607.2 → 509.2px |
| 390 | 606.8 → 538.8px | 1472.2 → 1400.2px |
| 320 | 639.8 → 538.8px | 1505.2 → 1400.2px |

픽셀은 이번 캡처 환경의 측정값이며 테스트의 고정 통과 기준이 아니다. 정상·최초 로딩·갱신·오류를 직접 확인했고 가로 넘침은 없었다. 대시보드의 네 크기별 전후 PNG는 바이트 단위로 동일했다.

## 이전 실패 7건의 원인

`admin-modal-followup-browser.mjs`는 현재 작업 시작 상태에서 11/18 통과, 7건 실패로 재현되었다. 요약 연동 직전 실제 작업 트리 스냅샷의 src/tests 371개 파일을 SHA-256으로 확인하여 별도 임시 앱에 복사·빌드한 뒤 같은 테스트를 실행했다. 이 환경에서도 동일한 7개 테스트가 같은 selector/DOM 검증에서 실패했다. HEAD로 이전 상태를 추정하지 않았다.

현재 `AdminOperationLogs`는 `AdminContentDialog` 대신 `AdminLogPanel`을 사용한다. 패널의 `AdminLogPreview direct`는 직접 조치를 제공하고 `onManage`를 넘기지 않는다. 따라서 예전 “이 댓글 관리” 버튼이 없고, 현재 콘텐츠 제목은 dialog가 아닌 panel 안에 있다. 이는 [11월 9일 확정 문서](admin-log-current-target-2026-11-09.md)의 구조와 일치한다. currentTarget:null fixture는 허용 계약이며 단건 현재 콘텐츠 GET은 성공하고 있었다. 실패 원인은 요약 연동 회귀나 지연 응답이 아니라 오래된 테스트의 동선·범위 가정이다.

| 기존 실패 | 유지한 검증 목적과 변경 |
| --- | --- |
| parent management retains comment conditions after changed=false | 현재 게시글 모달에서 댓글 검색·페이지를 적용하고 changed=false 이후 조건 유지. 후속 댓글 목록 GET을 지연시킨다. 응답과 일치하게 fixture의 현재 게시글도 이미 숨김 상태로 설정한다. |
| explicit close exits entire internal history before Back | 현재 운영 기록 패널의 선택 URL·닫기·행 포커스·Back 재선택·Forward 닫힘을 검증. 더 이상 존재하지 않는 내부 모달 이동/한 번에 다른 메뉴 복귀를 강제하지 않는다. |
| compact comments and historical/current summary (1440/320) | 게시글 댓글 펼침/접힘과 내용 유지 검증은 그대로. 과거/현재 운영 정보 제목은 현재 패널에 한정하여 확인하고 가로 넘침 검사 범위에 패널도 추가한다. |
| close after reload does not assume previous list | 패널을 새로고침/selected URL 직접 진입한 뒤 닫아 선택 해제·정렬 유지, Back/Forward와 URL·화면 일치를 확인한다. 폐기된 view=manage 동선을 복원하지 않는다. |
| parent comment action corrects last page | 현재 게시글 댓글 관리 진입에서 숨김 후 마지막 페이지 보정·검색어·상태 조건·POST 1회 검증을 유지한다. |
| parent anchor refresh failure keeps subtree | 현재 부모 게시글 GET 실패를 주입해 댓글 조건·하위 화면 유지, 조치 잠금, GET 복구 후 잠금 해제를 검증한다. 폐기된 중간 댓글→부모 앵커 화면을 전제로 하지 않는다. |

운영 기록·게시글 관리 제품 코드는 수정하지 않았다. assertion 삭제/테스트 비활성화/임의 sleep 증가로 해결하지 않았다. 기존 18개 시나리오가 현재 경로에서 모두 통과했다. 비교 앱의 환경 파일은 복사하지 않고 공개 localhost API 주소만 지정했다. 임시 의존성 심볼릭 링크는 Turbopack 제한으로 빌드 실패하여 의존성을 로컬 복사한 뒤 동일 빌드에 성공했다. production 서버 포트만 달랐으며 실제 세션 동작이 아닌 동일 mock 환경을 비교했다.

## 실제 로컬 연동

사용자 승인에 따라 기존 로컬 seed의 localhost DB 확인·PasswordEncoder·신규 INSERT 방식으로 이번 검증용 3계정만 만들었다. 운영 코드/보안 필터/DB 마이그레이션은 바꾸지 않았고, 기존 회원을 승격하거나 비밀번호를 변경하지 않았다. 각 계정의 정상 로그인과 역할을 확인한 후 게시글·댓글·신고 생성과 처리는 실제 HTTP API와 세션/CSRF로 수행했다.

- fixture: `summary-review-d52a2362`
- 신규 회원: 관리자 #41, 작성자 #42, 신고자 #43
- 신규 게시글: #105, #106 / 신규 댓글: #170 (#105 소속)
- 신규 신고 #10: #105를 resolve → RESOLVED / NO_CONTENT_ACTION
- 신규 신고 #11: 댓글 #170을 dismiss → DISMISSED / NO_CONTENT_ACTION
- 신규 신고 #12: #106을 hide-and-resolve → RESOLVED / CONTENT_HIDDEN
- 처리마다 처리 대기 -1, 오늘 종결 +1, 오늘 접수 불변을 서버 응답과 카드에서 확인했다. 전용 상세에서 목록 복귀와 처리 후 요약 GET 실패/GET만 재시도를 확인했다. 성공한 POST는 각 1회였다.
- 실제 대시보드 모달 처리만 미실행: 신규 신고가 오래된 접수 상위 5건에 포함되지 않았다. 기존 신고 처리나 날짜 조작으로 진입 조건을 만들지 않았다. 이 경로는 모의 API 테스트로 검증했다.
- 검증 데이터는 식별 가능하도록 그대로 남겼다. 기존 일반 데이터는 변경하지 않았다. 비밀번호·쿠키·토큰은 검토 자료에 포함하지 않는다. 후속 정리는 해당 fixture 소유 관계를 확인한 뒤 별도로 수행한다.

명령별 결과·비교 기록·원본 캡처·소유 데이터 변경 내역은 이번 검토 ZIP에 포함한다. 이전 작업 테스트 수치를 이번 실행으로 재사용하지 않는다.
