# IYUM P03 → Figma Make 전달 문서

작성·화면 확인: **2026-09-26 (Asia/Seoul)**. 기준: 이 날짜에 읽은 로컬 P03 구현. 이번 산출물은 통합 준비 문서이며 디자인 승인·실서비스 통합·정책 재조사·사용자 검증 완료를 뜻하지 않는다.

## 1. 목적과 자료의 역할

IYUM의 목적은 **“장애인이 필요한 정보를 찾는 시간과 어려움을 줄이고, 공식 정보와 실제 경험을 연결하여 더 나은 선택을 돕는다.”** 초기에는 청각장애인과 가족을 중심으로 공식 정보, 쉬운 설명, 질문·답변, 경험을 연결하고 경험이 검색 가능한 지식으로 쌓이는 방향을 지향한다.

P03은 이 서비스 안의 **보청기 건강보험 지원 안내**다. 보청기·장애등록·지원제도를 잘 모르는 당사자와 아동·청소년 보호자가 센터 방문 전에 전체 과정, 현재 위치, 지금 할 일, 기관에 물어볼 질문을 이해하는 것이 목적이다. 모든 서류와 행정 절차를 혼자 처리하게 만드는 도구가 아니다. 개인의 자격·등록·지급액을 판정하는 서비스도 아니다.

## 2. 실제 조사 범위와 발견 사항

### 2.1 IYUM 게시 디자인

데스크톱 브라우저에서 홈, 공통 헤더·주 메뉴, 커뮤니티 허브, 복지 메뉴 진입 결과를 확인했다.

- 헤더: 현재 표기는 ‘장애인플랫폼’, 로그인·회원가입 링크. 주 메뉴는 홈 / 커뮤니티 / 복지·지원정보 / 병원·전문기관 / 보조기기다.
- 홈: ‘필요한 장애 관련 정보를 찾아보세요’와 통합 검색 → 핵심 서비스 네 항목 → 커뮤니티·복지 지원정보 목록 → 병원·전문기관 → 보조기기. P03이 홈 검색이나 커뮤니티를 대체하면 안 된다.
- 시각 스타일: Noto Sans KR, 따뜻한 흰색 배경, 검정에 가까운 본문, 남색 링크·활성 메뉴, 얇은 구분선, 장식이 적은 목록·카드. 홈 h1 실측 28px/700, 주요 영역 h2 16px, 검색 버튼 높이 44px, 버튼 배경 `#1A1918`, 헤더 배경 `#FAFAF8`였다. 이는 관찰값이며 승인된 전사 토큰 명세가 아니다. 본문·상태의 위계는 P03 읽기에 맞게 조정할 수 있다.
- [커뮤니티 허브](https://ochre-bead-10600476.figma.site/community): 글 유형 ‘일반 / 질문·답변 / 경험·후기’, 주요 주제 ‘자유·일상 / 보청기 / 인공와우 / 치료·재활 / 의사소통 / 취업·직장 / 복지·생활’, 최근 게시글, 글쓰기 진입이 있다. ‘보청기’ 주제 링크의 목적지는 `/community/posts?topic=보청기`다. 해당 필터 목록·개별 글 상세와 실제 사용자 작성 여부는 이번에 검증하지 않았다.
- [복지·지원정보](https://ochre-bead-10600476.figma.site/welfare): 헤더와 메뉴는 유지되지만 본문은 **‘준비 중입니다.’**다. 이미 완성된 지원정보 목록이 있는 것으로 전제하지 않는다.
- 홈의 지원사업·기관·제품 일부 링크는 `#welfare-1` 같은 임시 앵커다. 기존 홈/커뮤니티의 같은 게시글 ID에도 제목·날짜·댓글 수 차이가 관찰됐다. 화면에 제목이 있다는 이유만으로 실제 후기나 정책 변경 사실로 인용하지 않는다. 예시 운영자·주소·연락처를 실제 IYUM 사업자 정보로 재사용하지 않는다.
- Make 편집 링크에서는 파일명, 버전 46 표시, 일부 기존 작업 기록과 홈 미리보기를 읽을 수 있었다. 비로그인 화면의 채팅 입력은 비활성이었다. Make 소스 전체·게시 버전 매핑은 확인하지 않았고 직접 편집·프롬프트 전송은 하지 않았다.

## 3. 통합 위치와 화면 관계

### 3.1 권장 통합안 — 기존 구현 사실과 구별되는 제안

1. **홈:** 검색과 핵심 서비스 네 항목을 유지한다. 기존 ‘복지·지원정보’ 영역의 첫 안내 항목으로 ‘보청기 건강보험 지원 안내’를 넣는다. 설명은 ‘센터 방문 전, 지원 과정과 내 상황을 확인하고 물어볼 질문을 준비하세요.’, 단일 진입 문구는 ‘지원 안내 보기’다. 지원금 액수를 홈의 보장 혜택처럼 강조하지 않고 접수 중 배지·가짜 마감일도 붙이지 않는다.
2. **복지·지원정보:** `/welfare`의 준비 중 본문에 최소한의 안내 목록을 만들고 검증된 P03 한 항목을 연결한다. 별도 지원제도 데이터베이스나 가짜 지원사업 목록을 만드는 작업으로 확장하지 않는다.
3. **P03:** 같은 IYUM 헤더와 주 메뉴 아래, ‘복지·지원정보 > 보청기 건강보험 지원 안내’의 위치를 알린다. 기존 `/validation/hearing-aid-health-insurance`를 우선 유지한다. 새 운영 경로는 아직 확정하지 않으며 변경 시 기존 공개 앵커와의 매핑을 보고한다. 외부 Vercel 페이지 링크만 붙이는 것은 디자인 통합 완료가 아니다.
4. **커뮤니티:** P03의 상담 질문 뒤 또는 상세 안내 마지막에 일반 탐색 링크를 둘 수 있다. 기존 보청기 주제 경로의 실제 목적지를 먼저 확인하고, 동작하면 ‘보청기 관련 커뮤니티 둘러보기’ 정도의 보조 링크로 연결한다. 미확인이면 연결 위치만 작업 보고에 제안하고 실제 UI에 빈 후기 카드·비활성 가짜 기능을 늘리지 않는다. 개인 경험은 공식 자격·지급 근거와 별도 제목/라벨로 구분한다. 설문 답변을 게시글 초안·URL에 자동으로 넘기지 않는다.

기존 홈의 검색·커뮤니티를 P03 전용 랜딩으로 바꾸거나 메인 메뉴를 추가로 늘릴 필요가 없다. 공통 서비스 탐색과 ‘내 결과로 돌아가기’는 서로 다른 목적이므로 구분한다. P03의 결과 보존은 **P03 내부 왕복**의 계약이다. 홈·커뮤니티로 완전히 나갔다가 돌아올 때의 보존은 현재 구현이 없는 새 결정이므로 보장한다고 쓰지 않는다.

### 3.2 화면과 섹션 구분

현재는 하나의 Next.js 경로 안에서 `summary / guided / result / reference / registry`를 전환한다. 별도 페이지 5개가 아니다. 숨긴 설문 컴포넌트를 계속 유지해 답변·제품 문맥을 보존한다.

| 보호자·양쪽 지원 | 전체 기준의 `#one-or-two` 섹션 한 개 | 요약·목차·한쪽 비용 카드·모든 결과 | 제목 아래와 하단 동일한 복귀. 결과 없음 → 요약. 공통 안내 방문으로 자격·상태를 재판정하지 않음 |
| 질문 바로가기 | 결과/보호자 내부 앵커 | ‘지금 할 일 보기 ↓’ / ‘병원·센터 질문 보기 ↓’ | 제목 초점 이동. 질문을 별도 편집 페이지로 만들지 않음 |
| 제품 확인 | 결과 내 기본 접힘 `ProductLookup` + `registry` 보기 | ‘추천받은 모델이 있다면 확인하기’ / 참고의 `#registry-check` | 같은 선택 제품 문맥 사용. 참고에서 조회했다면 참고의 센터 상담 준비로 복귀; 기존 결과 문맥 유지 |
| 검사 조건·공식 계산 근거·서류·자격 도움말 | 현재 보기 안의 disclosure | 각각의 summary/도움말 | 선택적으로 펼치며 별도 페이지나 필수 질문으로 바꾸지 않음 |

공개 참고 앵커: `#registration-help`, `#eligibility`, `#one-or-two`, `#benefit`, `#steps`, `#before-buying`, `#sources`. `#scope`, `#previous-benefit`, `#documents`는 관련 상세를 연다. 과거 `#prescription`→`#prescription-help`, `#document-details`→`#documents`, `#user-preparation`/`#faq`→`#before-buying`, `#experiences`→`#full-criteria` 호환이 있다. `#consultation-preparation`은 별도 질문 편집 화면이 아니라 기존 결과 또는 첫 질문으로 연결된다.

## 4. 질문·결과 콘텐츠 사용법

**정확한 질문·선택지와 다음 목적지는 §10, 15개 결과별 전체 문구는 §11에 있다.** R01~R15는 이 전달 문서의 비교용 번호이며 사용자 UI에 표시할 번호가 아니다. 모든 사람이 Q1~Q4를 전부 거치는 것으로 구현하지 않는다.

- Q1의 등록 완료 외 네 답변은 Q1에서 결과가 나온다.
- 등록 완료 후 Q2 의료급여는 Q2에서 결과가 나온다.
- Q2 건강보험/모름은 Q3으로 진행한다. Q3 처방 없음/모름은 그 자리에서 결과가 나온다.
- Q3 처방 받음만 Q4 지원 이력을 묻는다. 건강보험 5개 + 보험 미확인 5개 + 등록 전/모름 4개 + 의료급여 1개 = **15개 결과 경로**다.
- 지원 이력 미확인과 보험 자격 미확인은 별개의 정보다. 같은 결과 제목을 쓰더라도 답변 사실·미확인 항목·질문이 다른 경로를 합쳐 버리지 않는다.

### 4.1 현재 위치의 의미

전체 큰 흐름은 **등록 확인 → 병원 처방 → 구입·착용 → 검수·청구 → 이후 관리**다. 질문 중에는 현재 질문 주제를, 결과에서는 실제 답변으로 정리한 상태를 표시한다. Q1은 등록, Q3은 처방 강조. Q2 보험 자격·Q4 지원 이력은 특정 단계 완료로 표시하지 않는다.

여정의 단계 설명 원문은 다음과 같다.

| 단계 | 기관 | 설명 |
| --- | --- | --- |
| 등록 확인 | 이비인후과 · 주민센터 · 국민연금공단 | 검사·진단 자료를 제출하고 심사를 거쳐 청각장애 등록 결과를 확인해요. |
| 병원 처방 | 이비인후과 | 장애등록용 진단과 별도로, 지원금 신청용 보청기 처방전을 받아요. |
| 구입·착용 | 보청기센터 · 판매업소 | 제품과 비용을 상담하고, 지원 절차를 확인한 뒤 구입해 착용해요. |
| 검수·청구 | 건강보험 결과: 이비인후과 · 위임 청구: 판매업소 / 직접 청구: 국민건강보험공단 | 구입 후 병원에서 착용 효과를 확인받고 지원금을 청구해요. |
| 이후 관리 | 보청기센터 | 구입 후에도 보청기를 조절·관리하며 다음 방문 일정을 정해요. |

검수·청구의 기관 표기는 의료급여 결과에서 ‘이비인후과 · 청구 절차는 주민센터에서 확인’, 보험 자격 미확인/아직 묻지 않은 결과에서 ‘이비인후과 · 건강보험 청구: 판매업소 위임 또는 국민건강보험공단’으로 구분한다. 의료급여 결과에는 ‘아래는 기관별 큰 흐름이에요. 의료급여의 신청·승인과 청구 순서는 구입 전 주민센터에서 확인하세요.’, 건강보험을 확인하지 않은 다른 결과에는 ‘아래는 기본 흐름이에요. 보험 자격에 따라 구입 전 승인과 청구 절차가 달라질 수 있어요.’를 유지한다.

결과의 상단 과정 표시에서 등록 관련 R01~R04는 등록, 건강보험 처방 관련 R06~R07은 처방, 첫 지원 R08은 구입·착용을 강조한다. 의료급여 R05·이력 확인 R09~R10·보험 미확인 R11~R15는 단일 현재 단계 강조 없이 확인 필요 문구를 표시한다. 스크롤로 읽는 위치가 변해도 답변 기반의 현재 상태는 바뀌지 않는다. 아래 상세 여정의 완료/현재/확인 필요/이후 과정 라벨은 §11에 별도로 적었다.

등록 내부 흐름은 검사·진단(이비인후과) → 등록 신청·자료 제출(주소지 주민센터) → 장애정도 심사(국민연금공단) → 등록 결과 확인(주민센터). 검사 중은 첫 항목, 심사 대기는 세 번째 항목에 ‘지금’을 표시한다. 단순 난청 진단은 청각장애 등록 완료가 아니다.

## 5. 반드시 보존할 동작

| ID | 보존 계약 |
| --- | --- |
| B01 | 답변 변경은 해당 질문 뒤의 기존 답변을 제거하고 결과·다음 행동·질문·복사문을 함께 갱신한다. ‘이전 질문’은 앞 질문을 다시 보여준다. 새 결과의 비용 상세는 기본 접힘으로 돌아간다. |

| B09 | 질문/결과 전환, 빠른 이동, 참고 복귀는 목적지 제목으로 초점을 이동한다. 필요하면 닫힌 상위 상세를 먼저 연다. 고정 헤더와 과정 표시의 실제 높이를 고려해 제목이 가려지지 않게 한다. 동작 줄이기 설정에서는 부드러운 스크롤을 강요하지 않는다. |
| B10 | 선택지는 native button과 선택 상태 전달, 상세는 native details/summary를 우선. 도움말은 클릭·터치·Enter/Space, `aria-expanded`·`aria-controls`, 고유 ID, 명확한 focus-visible을 제공한다. 숨긴 보기는 탭 순서·접근성 트리에서도 제외한다. |
| B11 | 복사·복귀·주요 링크의 충분한 누름 영역(최소 44px)을 유지한다. 공통 복사 버튼에 필요한 스타일을 직접 연결해 부모 영역 밖에서 브라우저 기본 버튼으로 돌아가지 않게 한다. |

기존 복사문 구조:

```text
IYUM · 센터 방문 전 상담 질문
내 상황: {현재 결과 제목}
{답변 사실의 라벨}: {해당 사실}  ← 각 사실마다 한 줄

먼저 확인할 곳: {기관}
문의할 내용: {이렇게 물어보세요 문장}

1. {첫 상담 질문}
   확인할 것: {질문의 목적}
2. {두 번째 상담 질문}
   확인할 것: {질문의 목적}
3. {세 번째 상담 질문}
   확인할 것: {질문의 목적}
```

문장을 합칠 때 공백 또는 줄바꿈을 명시한다. 예: ‘처방전은 받았어요.현재…’가 되면 안 된다. 개인별 다음 행동과 보호자 공통 ‘지금 확인할 일’을 같은 상태 값으로 덮어쓰지 않는다.

## 6. 정책·금액·공통 안내 — 현재 구현의 보존 기준

아래는 이번에 정책을 새로 조사한 결과가 아니라 **현재 구현 및 기존 정책 검증 기록의 전사**다. 실제 적용은 공단/관련 기관 확인을 유지한다. 공식 URL·확인일은 §12에 모두 적었다.

### 6.1 시작 안내와 전체 기준

시작 화면의 핵심 문구:

- 제목: ‘보청기센터에 가기 전, 지원 과정부터 알아보세요’
- 설명: ‘청각장애 검사 중이거나 등록 결과를 기다리고 있어도 괜찮아요. 전체 과정에서 내 위치를 알아보고, 센터에서 물어볼 질문을 준비하세요.’
- 주 행동: ‘내 상황 확인하기’. 보조: ‘전체 기준 보기’, ‘아동·청소년의 양쪽 지원 알아보기’.
- 30초 요약: ‘등록 확인 → 처방 → 구입·착용 → 검수·청구 → 이후 관리로 이어져요.’ / ‘센터에서는 제품 상담과 신청 지원 범위를 물어보세요.’ / ‘한쪽 지원 기준액 131만 원은 제품·관리 비용을 나누어 지원하는 구조예요.’
- 범위: ‘최종 급여 자격을 판정하는 페이지가 아닙니다. 개인별 적용은 공단에서 확인하세요.’

전체 기준은 아래 **7개 섹션** 순서다. 결과의 정보 순서와 다른 읽기용 참고 화면이며, 결과를 이 긴 문서로 대체하지 않는다.

| 섹션 | 유지할 핵심 내용·선택형 상세 |
| --- | --- |
| 청각장애 등록 | ‘병원에서 난청 진단을 받는 것과 청각장애 등록은 달라요.’ 진단 자료 제출·심사를 거치는 행정 절차. 처음이면 주소지 주민센터에서 신청 방법/병원 안내. 이미 진단 자료가 있다면 제출 가능 여부 확인. 등록 내부 4단계와 국민연금공단/국민건강보험공단 역할 구분. 문의 예: ‘청각장애 등록을 처음 신청하려고 해요. 어떤 병원 검사와 서류가 필요한가요?’ |
| 지원 대상 | 청력장애로 등록된 청각장애인 중 건강보험 가입자·피부양자. 전문의의 보청기 필요 판단과 지원금 신청용 처방전, 등록 제품·업소, 검수·청구. ‘예전에 지원받았다면 언제 다시 받을 수 있나요?’와 ‘의료급여 대상이거나 보험 자격을 모르겠어요’를 접어서 제공 |
| 아동·청소년 양쪽 지원 | §6.3의 같은 안내 한 곳. 보호자 전용 설문을 추가하지 않음 |
| 지원 금액 | §6.2의 한쪽 카드 기본 노출. 실제 지급액 조건만 선택형 상세 |
| 5단계 진행 절차 | 등록·처방·구입·검수·관리. 위임 청구 시 판매업소, 직접 청구 시 공단. ‘이미 구입했는데 등록·처방 절차를 거치지 않았어요’ 상세를 유지 |
| 센터 상담 준비 | 아래 공통 질문 3개, 제품 조회 링크, ‘직접 청구하려면 서류를 어디서 받나요?’ 상세 |
| 공식 출처 | 자료명·기관·원문 링크·범위별 확인일. 원문은 새 탭으로 열림을 알림 |

추가 조건 원문:

- ‘보청기의 내구연한은 5년이에요. 지원받은 기기를 사용하는 기간의 기준으로, 5년마다 자동 입금된다는 뜻은 아니에요.’ 새 구입 전 공단에 이전 구입·급여 이력과 다시 지원받을 시점 확인. 기간 내 교체도 사유별 확인.
- ‘의료급여는 건강보험과 신청 절차가 달라요.’ 구입 전에 주소지 주민센터에 사전 절차 문의. 건강보험 자격·본인부담 경감 적용은 공단에 온라인 개인 상담 또는 지사 방문으로 문의. 온라인 상담은 로그인 필요이며 자동 자격 조회가 아니다.
- ‘구입했다고 무조건 지원되거나 지원이 불가능하다고 단정할 수는 없어요. 처방일·구입일·장애등록일과 구입 자료를 가지고 국민건강보험공단에 적용 가능 여부를 먼저 확인하세요.’

참고 화면의 공통 센터 질문:

1. ‘공단 등록 판매업소인가요? 추천해 주신 정확한 모델명과 급여 등록 여부도 알려주세요.’
2. ‘제가 내는 총금액은 얼마인가요? 초기·후기 관리와 수리 비용은 어떻게 나뉘나요?’
3. ‘청구를 맡길 수 있나요? 제가 직접 병원에 가거나 받아올 서류는 무엇이고, 다음 방문은 언제인가요?’

서류는 기본 노출 목록을 늘리지 않고 선택형 상세로 유지한다. 병원: 지원금 신청용 보청기 처방전·검사 자료와 구입 후 검수확인서. 판매업소: 구매 계약서·영수증 등 구입 증빙과 제품 바코드 확인 자료. 공단: 지급청구서와 위 자료 제출, 추가 자료·접수 방법 사전 확인. ‘판매업소에 위임한다면 위임장·신분증 사본 등 본인이 제공할 자료를 안내받으세요. 병원에서 받아야 할 자료까지 센터가 모두 대신해 주는 것은 아니에요.’

### 6.2 한쪽 비용 카드

표는 전달을 위한 데이터 명세다. 디자인에서는 **처음 청구 카드 전체 → 이후 청구 카드 전체 → 전체 합계** 순서를 유지한다. 카드 안의 왼쪽은 계산 기준·비용 구성·청구 시점, 오른쪽은 ‘자격별 최대 지원액’. 모바일은 각 카드 안에서 왼쪽 정보 → 오른쪽 정보 순서로 쌓는다.

| 카드 | 계산 기준·비용 구성 | 청구 시점 | 건강보험 일반 대상 · 90% | 차상위 본인부담경감 대상자 · 100% |
| --- | --- | --- | --- | --- |
| 처음 청구 | ‘지원금 계산 기준’ / 기준액 111만 원 / 제품 91만 원 + 초기 관리 20만 원 | ‘구입 후 1개월이 지난 뒤 병원 검수확인을 받고 청구해요. 두 비용은 함께 지급돼요.’ | 최대 99만 9천 원 | 최대 111만 원 |
| 이후 청구 | ‘관리비 계산 기준’ / 후기 적합관리 / 연 5만 원 × 최대 4회 / 기준액 합계 20만 원 | ‘구입 1년 후부터 5년까지의 관리 비용이에요. 매년 1회 이상 실제 관리를 받은 뒤, 연 1회씩 따로 청구해요.’ | 연 최대 4만 5천 원 / 4회 합계 최대 18만 원 | 연 최대 5만 원 / 4회 합계 최대 20만 원 |
| 전체 합계 | ‘전체 지원금 계산 기준’ / 전체 기준액 131만 원 | ‘처음 청구와 이후 관리 비용을 합한 금액이며, 한 번에 지급되는 돈은 아니에요.’ | 총 최대 117만 9천 원 | 총 최대 131만 원 |

기본 노출을 유지할 문구:

- ‘기준액은 건강보험 일반 대상과 차상위 본인부담경감 대상자가 공통으로 사용하는 지원액 계산 한도예요. ‘적합관리’는 보청기를 잘 사용할 수 있도록 조절·관리하는 서비스예요.’
- ‘실제 지원액은 제품별 고시금액과 구입금액 등에 따라 달라져요. 100% 지원도 지원 대상으로 인정되는 금액 기준이에요.’
- 각 기준액 바로 아래: ‘이 금액이 그대로 지급되는 것은 아니에요. 자격별 최대 지원액을 확인하세요.’
- ‘초기 관리는 구입일부터 1년간, 후기 관리는 그 이후의 관리예요.’

기준액은 보통 본문 수준, 자격별 **최대** 지원액은 더 강조한다. 기준액을 차상위 전용 금액이나 모두에게 지급되는 돈처럼 표시하지 않는다. 자격명·지원율·금액은 한 묶음이며, 도움말 본문이 그 사이에 끼지 않는다.

‘내 지급액이 안내된 최대 금액과 달라질 수 있나요?’ 상세의 보존 문구:

> 건강보험은 기본적으로 지급기준금액의 90%를 지원해요. 제품의 고시가격이나 실제 구입가격이 낮으면 지원액도 줄어들 수 있어요. 후기 관리도 실제 비용과 지급 조건을 확인해야 해요.
>
> 차상위 본인부담경감 대상 등은 같은 건강보험 안에서 100% 지원이 적용돼요. 기준을 넘는 비용까지 모두 지원한다는 뜻은 아니에요. 본인의 경감 적용 여부는 국민건강보험공단에서 확인하세요. 의료급여는 별도 절차를 확인하세요.
>
> 제품별 고시가격에는 초기 관리비가 이미 포함되어 있어요. 고시가격에 20만 원을 다시 더하지 않아요.
>
> 날짜가 지나면 자동 입금되는 방식이 아니에요. 개인별 청구 가능일과 지급받을 계좌는 판매업소·공단에 확인하세요. 위임 청구 시에는 판매업소가 지급받을 수 있어요.

자격명 옆 [?] 도움말의 접근 가능한 이름은 **‘차상위 본인부담경감 대상자 설명’**. 제목 ‘차상위 본인부담경감 대상자란?’, 본문은 해당 자격의 모든 금액 아래에 펼친다:

> 소득·재산, 부양 요건과 질환·연령 등의 기준을 심사받아, 건강보험 의료비의 본인부담을 줄여주는 지원 대상으로 인정된 분이에요.
>
> 청각장애 등록만으로 자동 적용되지는 않아요. 의료급여와는 다른 건강보험의 지원 제도예요.
>
> 대상인지 모르겠다면 국민건강보험공단에 “제가 차상위 본인부담경감 대상자로 등록되어 있나요?”라고 확인해 주세요.

결과의 건강보험 상세는 **R08·R09·R10에만** 센터 질문 뒤에 표시한다. 한쪽 기준액의 분할 지급 요약은 노출하고 ‘구입 후 병원 확인·청구·관리는 어떻게 이어지나요?’, ‘지원 금액과 지급 조건 자세히 보기’, ‘직접 청구한다면 서류는 어디서 받나요?’는 각각 기본 접힘이다. R09·R10에는 ‘아래는 일반 기준이에요. 이번에 지원받을 수 있는지는 이전 이력을 확인한 뒤 알 수 있어요.’를 유지한다. R11~R15에 금액을 붙이지 않는다.

### 6.3 보호자·양쪽 지원

읽기 순서:

1. ‘아이의 보청기, 양쪽 모두 지원받을 수 있나요?’
2. 진입 문맥에 맞는 상단 복귀: ‘← 내 확인 결과로 돌아가기’ 또는 ‘← 30초 요약으로 돌아가기’
3. 대상 요약과 짧은 공통 안내
4. ‘지금 확인할 일’ + ‘병원·센터 질문 보기 ↓’
5. ‘병원에서는 어떤 검사 조건을 확인하나요?’ 기본 접힘
6. 양쪽 최대 금액 예시
7. ‘공식 근거와 양쪽 금액 계산 방법 보기’ 기본 접힘
8. ‘병원과 센터에서 이렇게 물어보세요’와 복사
9. 별도 아동 지원사업 안내
10. 상단과 같은 하단 복귀

기본 노출 문구:

> 이 건강보험 제도의 보청기 지원은 기본적으로 한쪽 기준이에요. **19세 미만의 청각장애 등록자**는 추가 검사 조건을 모두 충족하면 양쪽 보청기 지원이 가능해요.
>
> **나이만으로 양쪽 지원이 확정되지는 않아요.**
>
> 아래는 공통 안내예요. 개인별 지원 자격과 실제 금액은 확인이 필요해요.

‘지금 확인할 일’ 본문: **‘이비인후과에서 아이가 양쪽 지원 조건에 해당하는지 물어보세요. 검사 수치를 직접 해석하지 않아도 괜찮아요.’** 바로가기는 기존 기관별 질문 제목으로 초점을 옮긴다. 질문 본문을 여기서 반복하지 않는다. ‘안내를 읽어도 상태는 바뀌지 않아요’ 같은 구현 설명을 복원하지 않는다.

검사 조건 상세: 청력장애로 등록된 청각장애인 중 건강보험 가입자·피부양자이며 이비인후과 전문의가 일상생활에 도움이 된다고 판단하는 기본 요건에 더해 **다음 모두**가 필요하다.

- 19세 미만
- 양쪽 모두 80dB 미만의 난청 — dB(데시벨)는 청력검사에서 사용하는 소리 크기 단위
- 양쪽 말소리명료도 각각 50% 이상 — 들은 말소리를 얼마나 정확히 구별하는지 보는 검사
- 양쪽 순음청력역치 차이 15dB 이하 — 검사 소리를 겨우 들을 수 있는 크기의 두 귀 차이
- 양쪽 말소리명료도 차이 20% 이하

의식이 명료하지 않거나 보청기를 사용할 수 없다고 전문의가 판단하면 한쪽·양쪽 모두 적용에서 제외된다는 문구와 고시 별표 2 제4호 출처를 상세에 유지한다. 나이/검사 수치 입력이나 자가 판정 기능을 만들지 않는다.

금액 앞 기본 문구:

> **양쪽 지원 대상자로 인정된 경우**의 예시예요. 두 보청기 각각에 최대 지급 기준이 적용되고 후기 관리 조건까지 충족했을 때의 합계예요.
>
> 공식 기준에 따라 계산한 양쪽 최대 금액 예시예요. 실제 지원액은 자격과 제품·관리 조건에 따라 달라져요.
>
> 초기·후기 관리는 보청기를 잘 사용할 수 있도록 조절·관리하는 서비스예요.

| 자격 | 처음 최대 | 후기 연 최대 | 최대 4회 합계 | 전체 총 최대 |
| --- | --- | --- | --- | --- |
| 건강보험 일반 대상 · 90% | 199만 8천 원 = 한쪽 99만 9천 원 × 2 | 9만 원 = 한쪽 4만 5천 원 × 2 | 36만 원 | 235만 8천 원 |
| 차상위 본인부담경감 대상자 · 100% | 222만 원 = 한쪽 111만 원 × 2 | 10만 원 = 한쪽 5만 원 × 2 | 40만 원 | 262만 원 |

기본 노출 조건: 각 제품의 고시금액·구입금액과 관리 조건에 따라 실제 금액이 달라짐 / 100%도 인정 금액 기준 / 처음은 구입 후 1개월 경과 및 병원 검수 후 청구 / 후기는 구입 1년 후부터 5년까지 매년 실제 관리 후 따로 청구 / **전체 합계는 한 번에 지급되지 않음** / **아동이라는 이유만으로 100% 지원 자격이 되지 않음**, 경감 적용은 공단 확인.

공식 근거 상세의 구분과 계산식:

- 직접 명시된 기준: 시행규칙 별표 7 제1호 라목·라목 1)의 내구연한 내 1인당 한 번 일반원칙과 양쪽 장착 각각 1회 예외; 제3호의 기준액·고시금액·실구입금액 중 가장 낮은 지급기준금액과 90%/100%; 고시 별표 2 제4호의 양쪽 조건; 별표 5 아목 10)의 한쪽 기준액 131만 원(적합관리 40만 원 포함)·내구연한 5년; 제5조의2/별표 4의 초기 20만 원, 후기 연 5만 원·최대 4회 조건.
- ‘아래는 공식 기준을 적용해 IYUM에서 계산한 합산 상한이에요. 고시에 이 양쪽 합계 금액이 직접 적혀 있다는 뜻은 아니에요.’
- 한쪽 제품 91만 원 = 131만 원 − 관리 40만 원. 처음 111만 원 = 제품 91만 원 + 초기 20만 원.
- 일반: 처음 111만 원 × 90% × 2 = 199만 8천 원; 후기 5만 원 × 90% × 2 × 4 = 36만 원; 전체 199만 8천 원 + 36만 원 = 235만 8천 원.
- 경감: 처음 111만 원 × 100% × 2 = 222만 원; 후기 5만 원 × 100% × 2 × 4 = 40만 원; 전체 222만 원 + 40만 원 = 262만 원.
- 후기 관리는 급여를 받은 기기를 지속적으로 사용하고 실제 관리받는 조건이다. 각 기기의 최대 지급·관리 조건을 충족한다는 전제이며 개인별 지급 여부와 실제 금액은 공단 확인.

보호자 기관별 질문과 복사문은 §11 끝에 원문으로 제공한다. 별도 사업 안내는 ‘장애등록 기준에 해당하지 않는 아이는요?’ 아래 **건강보험 보청기 급여와는 다른 사업**임을 밝히고 복지로 ‘선천성 난청검사 및 보청기 지원’ 원문만 연결한다. 이 사업의 조건·금액을 건강보험 양쪽 금액 계산과 혼합하지 않는다.

## 7. 제품 선택 기능의 범위

- 현재 기능은 **공식 고시의 고정 사본 206개 제품 검색**이다. 공단 실시간 API·자동 갱신·센터 등록 조회가 아니다. 시행일 2026-04-16, 목록 확인일 2026-09-23을 유지한다.
- 입력: ‘모델명 · 제품코드 · 업체명’, 일부 이름 가능. 빈 입력 오류: ‘제품 모델명이나 제품코드를 입력해 주세요.’ 입력 변경·재검색 시 이전 선택을 확인 완료처럼 남기지 않는다.
- 검색은 NFKC·소문자화·공백/하이픈 차이를 정규화하되 모델 접미 문자/숫자를 제거하지 않는다. 모델명/코드 정확 일치를 우선, 그다음 모델/코드/업체명 부분 일치. ‘스타키’는 starkey/스타키, ‘포낙’은 phonak 별칭. 결과는 6개씩 더 보기, 정확한 모델을 직접 선택한다.
- 결과 없음: ‘이 목록에서 일치하는 제품을 찾지 못했어요.’ / ‘모델명과 제품코드를 다시 확인해 주세요. 검색 결과가 없다는 것만으로 미등록 제품이라고 판단할 수는 없어요.’
- 선택 후: 모델·업체·제품코드·고시가격과 출처/확인일. ‘내가 받는 지원금이나 실제 판매가격과는 다를 수 있어요.’ / ‘제품 등록 확인은 개인의 급여 자격 확인과 달라요. 판매업소 등록도 별도로 확인해야 해요.’
- 건강보험 + 처방 완료 + 처음 결과(R08)에서, 최신성 확인 상태인 선택 모델만 첫 상담 질문에 반영한다. 모든 결과의 질문을 무조건 모델 질문으로 바꾸지 않는다.
- 예: `D22018010015` / `Starkey Picasso 1000 CIC` 선택 시 ‘Starkey Picasso 1000 CIC을 제게 추천하는 이유와 비교할 수 있는 다른 제품은 무엇인가요?’
- 7일 기준 최신성 경고와 조회 화면의 ‘검증용 최신성 지연 예시’는 **프로토타입 확인용**이다. 공단 갱신 주기나 운영 SLA로 표시하지 않는다. 2026-09-30 00:00 KST부터 현 데이터는 기존 7일 규칙상 stale가 되어 R08의 모델 특정 질문이 일반 질문으로 돌아갈 수 있다. 확인일을 오늘로 바꾸거나 실시간으로 꾸며 이를 숨기지 않는다. QA 예시는 필수 사용자 단계로 승격하지 않는다.
- 별도 조회 보기의 센터 입력은 disabled, 제목은 ‘센터 등록정보 조회 준비 중’. 실제 센터 표본·조회 기능이 없으므로 임의 센터 결과·등록 뱃지를 생성하지 않는다.
- `source-unavailable`은 데이터 타입에 있지만 현재 UI가 네트워크 조회로 만들어내는 경로가 아니다. 보이지 않는 원격 오류/재시도 기능이 있다고 문서화하지 않는다. `RegistrySummary`도 현재 표시 경로에서 사용하지 않는 export다.

## 8. 디자인 적용 원칙

1. IYUM 헤더·탐색·타이포·선·버튼·카드를 재사용한다. P03의 녹색·둥근 모서리·현재 폭을 그대로 복제할 필요는 없다. 기존 IYUM 홈의 16px 영역 제목을 P03 전체에 기계적으로 적용하지 말고 질문/상태/본문의 위계를 만든다.
2. 시작의 주 행동은 ‘내 상황 확인하기’ 하나로 두고, 전체 기준과 보호자 진입은 보조로 둔다. 결과에서는 다음 행동과 센터 질문을 비용·서류보다 먼저 읽는다. 큰 금액 배너를 결과 상단에 끼워 넣지 않는다.
3. 단계 그림은 탐색 버튼 묶음이 아니라 이해를 돕는 표시다. 색 외에도 단계명·현재·완료·확인 필요 라벨을 유지한다. 검수·관리 내용을 읽는 것만으로 그 단계 완료/현재라고 바꾸지 않는다.
4. 공통 헤더를 고정한다면 과정 표시와 겹치지 않게 한다. 현 P03 헤더는 고정되지 않는다. 새 고정 헤더 높이까지 초점 이동 여백에 포함해야 한다. 높이 450px 이하처럼 읽을 공간이 부족하면 과정 고정을 해제하는 기존 의도를 유지한다.
5. 비용 카드의 두 자격을 혼합하지 않고 기준액은 보통 본문, 실제 최대 한도는 강한 위계. 색뿐 아니라 ‘계산 기준’/‘자격별 최대 지원액’, 배치·글자 크기로 구분한다. 금액과 ‘최대’를 분리해 잘리지 않게 한다.
6. 데스크톱: 전체 기준은 목차와 본문, 비용은 카드 안 두 영역. 390px/320px: 한 열, DOM과 시각 순서 일치, 처음 카드 전체 뒤에 이후 카드. 가로 스크롤·버튼 겹침 없이, 도움말 본문은 흐름 안에서 확장한다.
7. 상세의 선택적 노출을 유지한다. hover 전용 툴팁, 중첩 모달, 페이지를 벗어나는 질문 편집 등 새로운 조작을 늘리지 않는다. 기관별 역할·핵심 조건을 숨겨서 단순화하지 않는다.
8. 공식 정보·IYUM의 쉬운 설명/계산 예시·개인 경험은 구분한다. 실제 관련 콘텐츠가 확인되지 않으면 후기 카드·댓글 수·추천 순위를 만들지 않는다. P03 응답은 커뮤니티 활동이나 개인 프로필로 자동 연결하지 않는다.

1단계는 공통 디자인·홈/복지 진입·P03 시작·대표 R02와 R08 결과의 디자인/동작 초안이다. **전체 통합 완료가 아니다.** 2단계는 15개 결과, 참고·비용·보호자·제품·복사·왕복·접근성 연결과 V01~V12 점검을 포함한다. 완료 보고에 구현/미구현/미검증을 나눠 적고 실제 게시 URL을 제공하도록 한다.

## 10. 질문 원문과 선택 후 이동

### Q1. 청각장애 진단·등록은 어디까지 진행하셨나요?

설명: 병원 검사·진단 뒤에는 주민센터에 자료를 내고 심사를 거쳐야 등록돼요.

보조: 주민센터에서 청각장애 등록 완료 안내를 받았는지 떠올려 보세요. 다른 장애로 등록된 것과는 구분해요.

| 선택지 원문 | 내부 값(사용자에게 표시하지 않음) | 다음 질문/결과 |
| --- | --- | --- |
| 아직 등록을 위한 검사·신청 전이에요 | `planning` | R01 |
| 병원에서 검사·진단을 받고 있어요 | `assessment` | R02 |
| 등록 신청 후 심사 결과를 기다려요 | `waiting` | R03 |
| 청각장애 등록을 마쳤어요 | `registered` | Q2 |
| 어디까지 진행됐는지 잘 모르겠어요 | `unknown` | R04 |

### Q2. 건강보험과 의료급여 중 어디에 해당하나요?

설명: 직장·지역 건강보험이나 가족의 건강보험에 포함되어 있다면 건강보험이에요. 의료급여는 생활이 어려운 분 등의 의료비를 지원하는 별도 제도예요.

보조: 모르면 처방전 등 아는 내용부터 이어서 확인해요. 보험 자격은 미확인으로 남겨둘게요.

| 선택지 원문 | 내부 값(사용자에게 표시하지 않음) | 다음 질문/결과 |
| --- | --- | --- |
| 건강보험에 가입되어 있어요 (가족 포함) | `health` | Q3 |
| 의료급여 대상이에요 | `medical-aid` | R05 |
| 잘 모르겠어요 | `unknown` | Q3 (보험 미확인 유지) |

### Q3. 이비인후과에서 지원금 신청용 보청기 처방전을 받았나요?

설명: 장애등록을 위한 진단서나 보청기를 권유받은 것과 달라요. 지원금 신청에 쓰는 공식 서류는 ‘보조기기 처방전’이에요.

보조: 서류 이름이 기억나지 않으면 ‘잘 모르겠어요’를 선택하세요.

| 선택지 원문 | 내부 값(사용자에게 표시하지 않음) | 다음 질문/결과 |
| --- | --- | --- |
| 예, 지원금 신청용 보청기 처방전을 받았어요 | `yes` | Q4 |
| 아직 안 받았어요 | `no` | 건강보험이면 R06 / 보험 모름이면 R11 |
| 잘 모르겠어요 | `unknown` | 건강보험이면 R07 / 보험 모름이면 R12 |

### Q4. 이전에 보청기 지원금을 받은 적이 있나요?

설명: 처음 신청하는지, 이전 지원 이력을 확인해야 하는지 알아보기 위한 질문이에요.

| 선택지 원문 | 내부 값(사용자에게 표시하지 않음) | 다음 질문/결과 |
| --- | --- | --- |
| 처음이에요 | `first` | 건강보험이면 R08 / 보험 모름이면 R13 |
| 받은 적 있어요 | `previous` | 건강보험이면 R09 / 보험 모름이면 R14 |
| 기억나지 않아요 | `unknown` | 건강보험이면 R10 / 보험 모름이면 R15 |

## 11. 결과별 원문과 상담 질문

아래 내용은 `getGuidance`·`getJourneyStates`·`getQuestionPlan`의 현재 출력을 직접 추출했다. 이 절은 질문 원문과 함께 독립적으로 읽을 수 있는 콘텐츠 기준이다. 기본 질문 3개를 생략하거나 AI가 매번 새로 쓰도록 바꾸지 않는다. 제품 선택에 의한 R08 첫 질문 변경만 §7의 조건을 적용한다.

각 결과의 ‘확인할 항목’은 원본의 `pending` 데이터다. **상단 단계 강조가 없는 R05·R09~R15에서만** 여정 앞의 ‘구입 전 확인 필요’ 목록으로 별도 표시한다. 나머지 결과에 이 데이터를 추가 경고나 반복 설명으로 새로 노출하지 않는다. ‘상단 강조’와 ‘여정의 단계별 상태’도 구현 명세이며 그 문장 자체를 결과 본문에 중복 출력하지 않는다.

화면에는 아래 기관명과 질문을 그대로 3개 표시한다. R01~R15의 개인별 질문을 교체하지 않는다.

```text
IYUM · 보호자의 양쪽 보청기 지원 상담 질문
건강보험 공통 안내를 바탕으로 준비한 질문이며, 아이의 지원 자격이나 금액을 확정한 결과가 아니에요.

1. 병원 · 이비인후과
아이의 검사 결과가 건강보험 양쪽 보청기 지원 조건을 모두 충족하나요? 양쪽 지원을 위한 처방이 가능한가요?

2. 보청기센터 · 비용
양쪽을 구입하면 각 보청기의 지원액과 제가 부담할 총금액은 얼마인가요?

3. 보청기센터 · 관리
양쪽 보청기의 초기·후기 관리에 포함되는 서비스와 별도 비용, 다음 방문 일정은 어떻게 되나요?
```

보호자 복사 성공 안내: ‘보호자 질문을 기관명과 함께 복사했어요. 휴대폰 메모 등에 붙여 넣어 보관하세요.’ 실패 대응은 B05와 같다.

첫 단계는 전달 문서 1개 첨부 + 프롬프트 붙여넣기로 시작한다. 전체 저장소·node_modules·빌드 산출물·방대한 과거 검증 기록·여러 화면 캡처를 첨부할 필요가 없다. 게시 URL로 공통 디자인을 볼 수 있으므로 이번에는 별도 스크린샷 파일을 만들지 않았다.

Make가 원본 함수 구현이 필요하다고 명시하면 추가할 작은 원본 묶음은 `guided-content.ts`(질문·결과), `consultation-content.ts`(질문 선택), `registry-content.ts`(두 파일의 제품 의존성), `question-note.ts`(복사문 조합)다. 정책 상세 JSX가 추가로 필요하면 해당 `BenefitBreakdown.tsx` 또는 `BilateralGuide.tsx`만 제공한다. 핵심 문구는 이미 이 문서에 있어 첨부 소스 없이는 내용을 추정해야 하는 상태로 두지 않는다.

후속 검토 요청에는 **새 게시 URL + 1단계/2단계 중 어디까지 구현했는지 + Make가 보고한 미구현/미검증 항목**을 함께 전달하면 된다. Codex는 이 문서 V01~V12와 R01~R15 기준으로 비교하고, 외형 차이와 콘텐츠·동작 회귀를 분리한 후속 요청을 작성한다. 이번 문서 작성은 기존 앱 코드 통합·커밋·푸시·배포·Figma 직접 편집을 포함하지 않는다.
